# GhostVault Engineering Style & Principles

## 1. Главный закон
Минимум самописного кода, максимум проверенных библиотек. Готовые надежные пакеты с минимальным количеством строк кода всегда предпочтительнее самописных решений.

## 2. Стек библиотек
- HTTP & Proxy: `fastify`, `@fastify/http-proxy`
- SSE Stream Parser: `eventsource-parser`
- Схемы и валидация: `zod`
- Поиск подстрок: `aho-corasick-node`
- База данных: `better-sqlite3`
- UI / Dashboard: Tailwind CSS, Lucide

## 3. Архитектура: OOP First
- Классы вместо фабричных функций: `new VaultStore()` вместо `createVaultStore()`.
- Состояние, сетевые соединения и жизненный цикл инкапсулируются внутри классов.

## 4. Синтаксис и компактность
- Строгий запрет на `function () {}`: старый синтаксис функций запрещен.
- Строгий запрет на `{ return x; }`: запрещены фигурные скобки ради одного `return`.
- Приоритет стрелочных функций:
  1. Однострочный неявный возврат: `x => doWork(x)` или `_ => defaultValue`
  2. Блочный вид `{ ... }` — только если внутри реально несколько выражений или сайд-эффекты.
- Строгий запрет на комментарии: ноль комментариев в коде (никаких `//`, `/* */`, `JSDoc`).
- Плотный текст: если логика умещается в 1 строку вместо 3 без потери читаемости — пишем в 1 строку.

## 5. Модульность и размер файлов
- Размер файлов: строго 10–300 строк кода на файл.
- При приближении к 300 строкам — немедленная декомпозиция.
- Single Responsibility: один файл решает ровно одну задачу.
