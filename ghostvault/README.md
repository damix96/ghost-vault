# GhostVault

Локальный прокси и MCP-каталог переменных для AI-клиентов. Модель получает имена и токены переменных, например `$${<BASE_URL>}`; прокси маскирует значения и восстанавливает их в поддерживаемых полях ответа. Изменение значения сохраняет токен. Переименование меняет имя и может нарушить старые ссылки.

## Установка

Нужны Node.js 22.13+ и npm. Установка из собранного npm-архива:

```sh
npm install --global ./ghostvault-0.2.0.tgz
ghostvault start
```

Панель управления: http://127.0.0.1:8765/dashboard. Команды `ghostvault status` и `ghostvault stop` показывают состояние и останавливают сервер. Данные по умолчанию находятся в `~/.ghostvault/vault.db`; `--data-dir`, `--db` и `--port` задают свои пути и порт. Шифруются значения ручных записей, явно отмеченных как секретные; обычные переменные и вся БД целиком не шифруются.

| Параметр | Приоритет |
|---|---|
| Каталог служебных данных | `--data-dir`, затем `GHOSTVAULT_DATA_DIR`, затем `~/.ghostvault` |
| База | `--db`, затем `vault.db` в явно заданном `--data-dir`, затем `GHOSTVAULT_DB_PATH`, затем `vault.db` в выбранном каталоге |
| Порт | `--port`, затем `GHOSTVAULT_PORT`, затем `8765` |

При совместном использовании `--db` и `--data-dir` база остаётся по первому пути, credentials и служебные файлы — по второму. Те же параметры нужны для `status`, `stop` и настройки MCP. Прежний `npm run zen` без переопределения продолжает использовать `.cache/zen-live.db` относительно рабочего каталога; данные между путями автоматически не переносятся.

## Защищённые значения

На странице «Секреты» одна кнопка «Добавить переменную»; галочка «Шифровать» включает защищённое хранение. У существующей обычной записи также доступно «Защитить» без изменения значения, имени, токена и состояния замены. Зашифрованное значение заменяется через ту же форму с пустым полем; отключение шифрования пока не поддерживается. Переименование и удаление остаются отдельными действиями. Шифрование и замена в запросах к модели — независимые признаки.

В «Настройки → Скрывать зашифрованные данные в интерфейсе» можно скрыть только значения зашифрованных переменных; по умолчанию они видны владельцу. Обычные значения, имена, шаблоны и окружающий текст остаются видны. Выбор сохраняется в браузере и не меняет DPAPI, MCP или подстановки в трафике. Старый вызов показывает своё значение, даже если переменная уже изменена. Подсказка «Значение / Шаблон» описывает соответствие, а «От модели / Приложению» — подтверждённое восстановление. Полный ответ доступен рядом с фрагментами роли «Ассистент».

MCP-каталог возвращает `name`, необязательное `description` и `source`, без оригиналов и дублирующего `token`. Инструкции MCP задают построение `$${<NAME>}` и предупреждают: полный шаблон в ответе восстанавливается даже в кавычках и блоках кода.

| Платформа | Хранение ключей и проверка |
|---|---|
| Windows | DPAPI CurrentUser текущего пользователя; native x64 проверен на Node.js 22.13 и26.8.2 |
| macOS | AES-256-GCM, ключ в Keychain; проверено на тестовых подменах системного хранилища, настоящая macOS не проверена |
| Linux | AES-256-GCM, ключ в Secret Service; требуется доступный системный сервис, временный kernel keyring не используется; настоящая Linux не проверена |

Системное хранилище позволяет не держать ключ рядом с БД. Если provider или существующий ключ недоступен, операция завершается ошибкой; записи не переводятся в открытый вид. Это защита сохранённых значений, без изоляции от произвольного кода того же пользователя или администратора ОС. Перенос БД на другую ОС/учётную запись без её ключевого материала не восстанавливает секреты.

Защита существующей записи шифрует также её сохранённые архивные значения и заменяет известные значения в сохранённой диагностике подстановками. Старые внешние копии, резервные копии и выгрузки не стираются. Если очистку прежних открытых копий в рабочей БД после сохранения подтвердить не удалось, интерфейс показывает предупреждение; запись уже сохранена, повторять ввод не нужно. Актуальное состояние видно на странице переменных; следующая успешная запись повторяет очистку. Завершённая форма сохраняет историческое предупреждение о своей операции.

Экспорт сохраняет метаданные защищённых записей и архивов с `valueOmitted:true`, без значений и шифртекста. Такой файл не является резервной копией защищённых значений. Оригинал доступен владельцу в интерфейсе при выключенном скрытии; снятие защиты и переносимая резервная копия секретов пока не предусмотрены.

## Подключение MCP

Показать конфигурацию для клиента:

```sh
ghostvault setup --client codex
```

Поддерживаются `codex`, `claude` и `cursor`. Для записи укажите явный путь к конфигурации клиента. Сначала можно посмотреть изменение:

```sh
ghostvault setup --client codex --config /path/to/config.toml --dry-run
ghostvault setup --client codex --config /path/to/config.toml
```

Перед изменением существующего файла создаётся резервная копия. Посторонние настройки сохраняются по смыслу; TOML может изменить форматирование и комментарии. Повторный запуск без изменений не переписывает файл.

Настроенный stdio bridge сам запускает общий сервер при первом обращении. Несколько клиентов используют один Vault. Инструкции встроены в MCP; отдельный skill не нужен. Каталог читается по необходимости и может измениться вне текущей сессии. Подстановка токенов работает для запросов, проходящих через GhostVault-прокси; подключение только MCP не настраивает прокси клиента.

Инструмент `ghostvault_list_variables` по умолчанию возвращает включённые ручные переменные; `includeAutomatic: true` добавляет автоматические. Результат содержит имена, токены и описания, без значений. Смена значения сохраняет токен; уже выполняющийся запрос завершает свою подстановку, следующий использует новое значение. При переименовании старое имя перестаёт работать для новых запросов, если позднее не создана другая переменная с этим именем.

MCP передаёт правила в `instructions` и описании инструмента. Конкретный клиент решает, как включить их в контекст модели; универсальная проверка всех harness, resume и compaction не заявляется. Ранее загруженный каталог остаётся снимком, а не автоматически обновляемым списком.

Для ввода секретов инструмент `ghostvault_request_secret_input` получает только имена и операцию создания/обновления, затем инициирует открытие локальной формы. Значения вводятся человеком в форме, не в чате или параметрах MCP. `ghostvault_secret_input_status` возвращает состояние и сохранённые имена/токены; `ghostvault_cancel_secret_input` отменяет ожидающий ввод. Факт попытки запуска браузера сам по себе не подтверждает открытие окна.

Формы доступны и напрямую: `http://127.0.0.1:8765/vault-secret/new` и `http://127.0.0.1:8765/vault-secret/update?secrets=MY_API_KEY,BASE_URL`. Обновление заменяет значения существующих ручных записей и защищает их; старые значения не подставляются в поля. До 32 записей сохраняются одной операцией. Форма действует 10 минут; перезапуск сервера завершает несохранённые запросы, сохранённые значения остаются. При потере ответа форма проверяет статус без автоматической повторной отправки значений.

## Автозапуск и обновления

Windows: `ghostvault setup --autostart` показывает план, `ghostvault setup --autostart --apply` включает запуск после входа пользователя. Автоматическая регистрация запуска на Linux/macOS пока не поддерживается; доступны обычный запуск и MCP bridge.

Windows использует ярлык Startup и скрытый PowerShell helper. Setup проверяет доступность выполнения, не меняя системную политику. Это запуск после входа пользователя, без службы до входа и без постоянного перезапуска после сбоя. Следующее обращение через bridge снова выполнит проверку запуска.

Совместимый запущенный экземпляр используется повторно. Более старая подтверждённая версия заменяется; `ghostvault start -force` принудительно заменяет подтверждённый экземпляр. Чужой сервис на выбранном порту приводит к ошибке `Port already in use`.

При остановке сервер прекращает принимать новые запросы и даёт выполняющимся до 5 секунд на завершение. Затем оставшиеся сетевые запросы прерываются; их неполные ответы не считаются успешно завершёнными. Ещё до 2 секунд отводится на завершение обработчиков перед закрытием БД и освобождением порта. Если подключённый программно custom hook не завершает свою работу, остановка возвращает ошибку и сохраняет БД/порт; после завершения hook остановку можно повторить. `-force` использует тот же порядок завершения.

## Сборка из репозитория

В каталоге `ghostvault`: `npm run setup:dev`, затем `npm run build`. `npm test` запускает регрессионные тесты с изолированными каталогами и БД; `npm run test:mcp:agent` проверяет MCP. `npm pack` собирает backend/UI и создаёт архив для установки. Пользовательская установка архива не требует соседнего `ui-kit` или сборки исходников.

После сборки `npm run test:all` проверяет регрессии, переменные, MCP, процессы сервера, остановку зависших сетевых запросов, setup, хранение сессий и защищённые записи. `npm run test:secrets` отдельно проверяет providers, атомарную запись, публичные проекции и HTTP/MCP ввод; настоящие DPAPI сценарии выполняются на Windows. Отдельно shutdown-сценарии запускаются через `npm run test:shutdown`. Windows autostart проверяется во временном каталоге. `npm run stage:release -- --out /absolute/empty/directory` создаёт отдельную поставку; `npm run verify:release -- --stage /absolute/empty/directory` проверяет её после установки production-зависимостей. npm registry публикация — отдельное действие; наличие архива не означает, что пакет уже опубликован.
