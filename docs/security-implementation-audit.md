# GhostVault: аудит реализации и защиты секретов

Дата: 2026-10-24. Состояние: локальная рабочая копия после добавления простого мониторинга и провайдера `ghostvault-test`.

Смена требований 2026-10-25: [master-spec.md, §6.1–6.2](./master-spec.md) отделяет персистентные соответствия секретов от runtime-диалогов. Сессионный TTL Auto Vault больше не является требованием; целевая модель — последний вызов каждой сессии в памяти, без постоянной последовательности трафика. Она пока не реализована. Исторические STA-01 и строки соответствия ниже сохраняются как результаты прежнего аудита, а не актуальное требование внедрить TTL. Приоритеты реализации текущего согласованного этапа — в [roadmap.md](./roadmap.md).

## Заключение

**Реальные пароли пока нельзя считать защищёнными.** Подтверждены утечки зарегистрированных секретов в исходящем JSON, открытое хранение в SQLite/WAL, выполнение JavaScript через админский HTTP API и stored DOM XSS. Рабочий E2E с одним URL подтверждает конкретный функциональный сценарий, но не гарантирует отсутствие утечек других секретов.

Приоритеты ниже — порядок исправления в проекте, не формальные CVSS-оценки. `P0` блокирует использование с реальными секретами; `P1` исправляется до расширения совместимости и рабочего внедрения.

## Обновление после согласования функционального этапа

Следующая реализация описана в [фиксированных форматах сообщений](./protocol-formats.md). Таблица findings ниже сохраняет исходные результаты аудита.

| Finding | Текущее состояние |
|---|---|
| SEC-01 | Исправлен для целевых полей поддерживаемых JSON API: structured traversal и корректные escaped variants; добавлены regression checks |
| SEC-08/09 | Исправлены удаление обеих Map, исключение duplicate при manual save и manual-first masking/detection |
| SEC-02 | 2026-10-25: `/api/` проверяет Origin/Host/Sec-Fetch-Site; foreign Origin, `null`, cross-site/same-site browser requests и чужой Host получают 403 до выполнения обработчика. Собственная админка и non-browser requests без Origin разрешены. Модельные маршруты не затронуты. Это граница browser origins, не аутентификация локальных процессов; чтение секретов и запуск доверенных хуков остаются штатными функциями |
| SEC-03 | 2026-10-25: динамические inline JavaScript handlers заменены whitelist actions и JSON-аргументами в HTML data attributes. Копирование сохраняет quotes/backslashes/CRLF/Unicode, значение не интерпретируется как JavaScript; браузерный synthetic marker не исполняется |
| SEC-07 | 2026-10-25: удаление сессии/всей истории очищает SQLite, серверный memory history и last context. Generation guards не дают ответам начатых до удаления запросов записать удалённую историю заново. Правила секретов сохраняются |
| SEC-05 | Переклассифицировано по уточнённой модели доверия: обычное перенаправление доверенного upstream не считается багом. Старый synthetic redirect probe подтверждал поведение HTTP-клиента, а не реальную утечку на Zen. Дополнительная политика запрета redirect/передачи credentials не вводится |
| SEC-06 | По уточнённой области transport query/headers проходят без маскирования; это не считается дефектом фильтра промпта. URL внутри текста промпта остаётся целью замены |
| STA-06 | Добавлены фиксированные Responses и Gemini/Antigravity adapters с JSON/SSE fixtures; реальные облачные подключения не подтверждены |
| Остальные findings | Не исправлялись на этом этапе; шифрование хранения отложено по указанию пользователя |

Причины и механизмы обновления 2026-10-25: значения секретов должны быть данными обработчика, а не фрагментами JavaScript; HTML escaping не делает строку безопасной внутри inline JS. Удаление должно синхронно убрать обе копии истории; одной очистки SQLite недостаточно из-за memory fallback. Origin guard ограничивает служебный `/api/`, сохраняя модельный трафик и обычную локальную работу без нового логина. `ApiClient` теперь добавляет JSON Content-Type только при наличии body: пустые DELETE/POST раньше отклонялись Fastify как пустой JSON, поэтому browser deletion не доходил до обработчика.

Проверки: постоянный `test-admin-regressions` (в `npm test`, отдельно `npm run test:admin`), memory DB и локальный upstream; browser interactions проверяются изолированным `.cache/verify-ui.mjs`. Пользовательские данные, cloud inference и настройки providers для этих проверок не используются. Удаление является логическим удалением истории, не криптографическим стиранием SQLite/WAL или ранее экспортированных файлов.

## Причины и направление исправлений

| ID | Почему | Для чего исправлять | Как | Почему не иначе |
|---|---|---|---|---|
| SEC-01 | Поиск выполняется после `JSON.stringify`; `jsonEscaped` заменяет только `/`, игнорируя JSON-экранирование кавычек, backslash и переводов строк | Не выпускать зарегистрированные секреты | Маскировать структурированные строковые значения до сериализации; добавить итоговую проверку перед отправкой, включая изменения хуков | Четыре строковых представления не заменяют обработку JSON-структуры |
| SEC-02 | Нет admin authentication/Origin/Host boundary; dry-run использует `AsyncFunction` и `eval` | Ограничить чтение секретов и выполнение кода | Закрыть выполнение произвольного кода по HTTP по умолчанию; определить отдельный доверенный административный доступ | Скрытая вкладка и loopback не являются авторизацией; имя `HookSandbox` не создаёт изоляцию |
| SEC-03 | HTML escaping применяется внутри JavaScript-строки в inline `onclick` | Исключить выполнение данных как кода | Убрать inline handlers с пользовательскими значениями; использовать DOM listeners и данные отдельно от JS | Добавление одного escape для апострофа не решает все контексты HTML/JS |
| SEC-04 | Значения и журнал записываются в SQLite как обычный текст | Защитить данные на диске и минимизировать копии | Сначала определить минимально необходимый журнал; затем аутентифицированное шифрование и защищённый ключ по master-spec; предусмотреть миграцию старой БД | Шифрование только таблицы secrets оставит значения в transactions/WAL/backups; постоянный хеш не подходит для обратимой подстановки |
| SEC-05/06 | Заголовки и URL пересылаются практически напрямую; fetch автоматически следует redirect | Привязать credential к разрешённому назначению | Запретить автоматическую передачу credentials другому origin; явно определить политику redirect, headers и query | Простая проверка начального upstream URL не ограничивает последующие redirect |
| SEC-07/08 | БД, caches и два Map обновляются раздельно; `manual.delete(...) || auto.delete(...)` использует short-circuit | Сделать удаление достоверным | Централизованный жизненный цикл с согласованной очисткой БД, памяти, live UI и snapshots; вызывать оба удаления | Очистка одной таблицы/массива оставляет доступные копии; физическое стирание старых файлов требует отдельной политики |
| SEC-09/10 | Сортировка учитывает длину, но не tier; fingerprint использует общий первый фрагмент диалога | Сохранять приоритет политик и границы сессий | Явный manual/auto priority; явный client conversation ID и проверенные fallback-правила | Одинаковый system prompt не идентифицирует конкретный диалог |

## Соответствие спецификации

| Требование | Статус | Факт |
|---|---|---|
| Известный простой URL не покидает proxy в открытом виде | Частично | Положительный E2E есть; пароль со спецсимволами нарушает общий инвариант |
| Токен `$${<IDENTIFIER>}`, `[A-Z0-9_]+` | Частично | Генерация есть; API не валидирует алфавит |
| Четыре предвычисленных представления | Частично | Вычисляются; JSON-escaping недостаточен для JSON body; hit telemetry не учитывает Base64 |
| Ахо–Корасик, O(N) | Не реализовано | Последовательный поиск/замена по списку; паттерны компилируются во время scan |
| Приоритет manual, затем longest match | Не соответствует | SEC-09 |
| SQLite WAL | Реализовано с отклонением стека | Используется `node:sqlite`, master/engineering-style требуют `better-sqlite3`; решение описано в поздних документах, основной норматив не обновлён |
| DPAPI / AES-256-GCM, защищённый ключ | Не реализовано | SEC-04; POSIX `0600` также не задаётся явно |
| Auto Vault в пределах session, очистка по TTL | Не реализовано | STA-01 |
| Confirmation modes | Типы без поведения | Режим присутствует в config, но не управляет обработкой новых секретов |
| Cache-Inspect-Get, `__as_json`, selectors | Не реализовано | Соответствующих runtime-модулей и tools нет |
| Singleton daemon / micro-MCP / GUI bridge | Частично | HTTP daemon и MCP hooks есть; singleton bootstrap, cache tools и GUI bridge не реализованы |
| WPF confirmation | Прототип | `scripts/modal.ps1` не подключён к pipeline; есть прямое XML-встраивание значений, старый alias `$BANK_API_URL` и комментарии |
| SSE Chat Completions / Anthropic | Частично проверено | Есть fragmented alias/JSON escaping/stream reset tests; не полная protocol conformance suite |
| Outbound <0.5 мс, TTFB 40–50 мс | Не подтверждено | Benchmark под нагрузкой, разными размерами словаря и concurrency не проводился |

Саму спецификацию также нужно уточнить: заявление об отсутствии shell-конфликтов нельзя трактовать как разрешение исполнять сырой alias в Bash. В Bash `$$` имеет значение PID оболочки; до исполнения alias должен быть разрешён либо запрос отклонён. Основание: [Bash Special Parameters](https://www.gnu.org/s/bash/manual/html_node/Special-Parameters.html).

Roadmap указывает Node.js 20+, но реализация импортирует `node:sqlite`. Этот модуль добавлен в Node.js 22.5.0; без experimental flag доступен начиная с 22.13.0. Нужны зафиксированная поддерживаемая версия, `engines` и CI matrix. Источники: [Node.js SQLite](https://nodejs.org/download/release/latest-jod/docs/api/sqlite.html), [Node.js CLI](https://nodejs.org/download/release/v26.5.1/docs/api/cli.html).

## Инженерные правила

AST-проверка 44 файлов TS/JS/HTML/CSS: **0** нарушений диапазона 10–300 строк, **0** старых function declarations/expressions, **0** стрелочных функций с единственным блочным return, **0** подтверждённых комментариев. Литералы URL/regex/template исключались из поиска комментариев, чтобы не получать ложные срабатывания.

Этот результат не подтверждает 100% соответствие архитектуре. Вместо предусмотренных `@fastify/http-proxy`, `aho-corasick-node`, `better-sqlite3` используются собственная обвязка fetch, последовательные замены и `node:sqlite`. Эти решения нужно либо привести к нормативу, либо явно обосновать и закрепить в нём. PowerShell-прототип отдельно содержит `function Finish`, XAML-комментарии и прямую подстановку данных в XML; `test-popup.bat` короче 10 строк. Стандарт для вспомогательных скриптов требует уточнения, а не добавления бессмысленных строк.

## Артефакты и критерии завершения исправлений

Локальные воспроизводимые проверки и отчёты находятся в игнорируемой `.cache`:

- `security-audit-dynamic.mjs` — adversarial HTTP/browser/SQLite сценарии;
- `security-audit-dynamic.json` — результаты без исходных canary values;
- `security-audit-npm.json` — registry audit;
- `security-audit-style.mjs` / `security-audit-style.json` — инженерные проверки.

Следующие условия должны стать regression checks с обратными, безопасными ожиданиями:

1. Ни один зарегистрированный canary, включая спецсимволы, не восстанавливается из egress за исключением явно назначенного целевому провайдеру credential.
2. Чужой Origin/неавторизованный клиент не читает vault, history, SSE и не запускает код; admin privilege отделён от proxy request.
3. Данные секрета не интерпретируются как JS/HTML ни при рендеринге, ни при копировании/раскрытии.
4. Canary отсутствует в plaintext во всех постоянных файлах и логах; временные/резервные копии и ключи имеют определённый жизненный цикл.
5. Redirect не передаёт credential другому origin без явной политики.
6. Удаление/истечение срока очищает все предусмотренные копии; manual priority и session isolation воспроизводимы.
7. Каждое заявленное API-поколение и lifecycle хуков имеют отдельные проверки; неподдерживаемые случаи не проходят молча.

Порядок работ: закрыть административную границу и XSS → устранить egress leaks/redirect → сократить журнал и внедрить шифрование с миграцией → исправить lifecycle и session isolation → обновить зависимости и normative docs → расширять протоколы и измерять производительность.
