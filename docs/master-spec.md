# GhostVault Master Specification

Архитектурная спецификация и протокольные инварианты GhostVault (AI-Native Secrets Vault & In-Flight Masking Proxy).

Статус: норматив требований, не отчёт о полной готовности. Полный frontend-перенос на UI-kit завершён и развёрнут на `8767`; исходники — `ghostvault/frontend/`, generated `public/` не хранится в VCS, сборка локальная без CDN. Изолированный Chromium smoke и source-only воспроизведение сообщены владельцем как PASS; координатор проверил 51 live URL по HTTP/MIME/SHA. Пользовательская UX-приёмка, IME/AT/CSP/full matrix не подтверждены. Хранение последних вызовов в памяти и бюджет 200 МБ остаются отдельными нереализованными требованиями; экспорт настроек реализован с границами, описанными в [отчёте переработки UI](ux-redesign-implementation.md); последовательность вызовов ещё сохраняется в SQLite. Источники и границы: [roadmap.md](./roadmap.md); канонический UX: [frontend-ux-guide.md](./frontend-ux-guide.md).

## 1. Концепция и назначение

GhostVault — локальный шлюз безопасности, развернутый между средами исполнения AI CLI-агентов (Claude Code, Cursor, Antigravity) и внешними API языковых моделей (Anthropic, OpenAI).
- Внешняя модель и сетевые снифферы оперируют исключительно символическими псевдонимами `$${<NAME>}`.
- Локальная среда исполнения (bash, powershell, curl, скрипты) получает оригинальные значения секретов.

## 2. Спецификация псевдонимов

Формат символического токена:
`$${<IDENTIFIER>}`

Инварианты:
- Алфавит идентификатора: строго `[A-Z0-9_]+`.
- Отсутствие коллизий с шаблонизаторами и синтаксисом оболочек (Bash `${...}`, Jinja `{{ ... }}`, Helm, Terraform, PHP).
- Отсутствие доменных TLD, схем протоколов (`https://`), IP-адресов. Токен DLP-нейтрален.
- Регулярное выражение обратного поиска: `/\$\$\{<([A-Z0-9_]+)>\}/g`.

Обычное значение использует `$${<KEY>}`. Различающиеся кодированные представления используют отдельные идентификаторы, например `$${<KEY__GV_JSON1>}`, `$${<KEY__GV_JSON2>}`, `$${<KEY__GV_JSON3>}`, `$${<KEY__GV_URL>}`, `$${<KEY__GV_BASE64>}`. Обратная таблица связывает каждый такой alias с точным представлением, найденным на выходе, а не всегда с raw value. Одинаковые представления дедуплицируются. Идентификатор представления не должен совпадать с alias другого зарегистрированного секрета; при коллизии добавляется числовой суффикс.

## 3. Pre-computed Formats Index

При регистрации секрета `S` в хранилище предварительно вычисляются строковые представления:
1. `raw`: `S`
2. `urlEncoded`: `encodeURIComponent(S)`
3. `jsonEscaped`: `S.replace(/\//g, '\\/')`
4. `base64`: `Buffer.from(S).toString('base64')`
5. JSON string escaping без внешних кавычек, применённый последовательно один, два и три раза.
6. Slash-escaped варианты JSON и JSON-экранирование slash-escaped значения на тех же уровнях.

Один промпт может содержать все эти представления одновременно. Для точного roundtrip тип представления сохраняется в alias; URL/Base64 возвращаются в исходной кодированной форме, вложенный JSON сохраняет необходимое экранирование. Поддержка уровней JSON 1–3 относится к тексту внутри prompt, отдельно от сериализации внешнего API request. Восстановленные значения не сканируются повторно как aliases.

Поиск по всем представлениям выполняется алгоритмом Ахо-Корасик (`aho-corasick-node`) за один проход $O(N)$ от длины сканируемого текста.

## 4. Сетевой цикл и бюджет задержек (Latency Budget)

| Фаза | Протокол | Механизм обработки | Целевая задержка |
|---|---|---|---|
| Outbound (Запрос к LLM) | HTTP POST JSON | Синхронное сканирование тела запроса словарным поиском по предвычисленным форматам (`Real -> $${<NAME>}`) | < 0.5 мс |
| Inbound SSE Streaming | Server-Sent Events | Буфер скользящего окна (`SlidingBuffer`) размером `max(token_length) * 2` (~40–60 символов). Символы вне окна сбрасываются в сокет немедленно | TTFB 40–50 мс |
| Inbound Tool Calls | JSON Blocks | Буферизация аргументов вызова тула до события `content_block_stop`. Демаскирование `$${<NAME>} -> Real` перед передачей в CLI-агент | < 1 мс |

## 5. Приоритеты разрешения коллизий (Conflict Traps)

1. **Config / UI Order:** Порядок следования правил в конфигурации (ручные правила имеют приоритет над автоматическими).
2. **Longest Match First:** Среди нескольких пересекающихся кандидатов заменяется наиболее длинная подстрока (предотвращение частичной замены префиксов URL).

## 6. Персистентное хранилище и криптография

### 6.1. Конфигурация и соответствия секретов

- Персистентны: ручные соответствия `realValue ↔ alias` и прежние версии их значений для inbound-восстановления, legacy-автосекреты, правила обнаружения, маршруты/подключения, настройки прокси и хуков. Новые автоматически обнаруженные originals хранятся только в памяти процесса; после рестарта не загружаются. На диске остаются hashes выданных aliases без новых auto originals для запрета повторной выдачи токенов. Legacy-данные не очищаются автоматически. Реализованный контракт, API, ограничения single-runtime и миграция: [метки секретов](architecture/secret-label-templates-contract.md).
- Движок: SQLite WAL. Изначальный целевой драйвер — `better-sqlite3`; фактическая реализация — `node:sqlite`. Стандартный путь `~/.ghostvault/vault.db` может переопределяться точкой запуска; cloud gateway использует `.cache/zen-live.db`.
- Шифрование — отложенный этап, пока не реализовано: Windows CryptProtectData (DPAPI); POSIX AES-256-GCM с мастер-ключом в файле `0600`. Текущее открытое локальное хранение нельзя описывать как шифрование.

### 6.2. Данные последних вызовов: согласовано, пока не реализовано

| Объект | Целевая политика |
|---|---|
| Сессия мониторинга | В памяти процесса; один последний вызов на `sessionId`, без постоянной записи трафика и последовательности вызовов в SQLite |
| Последний вызов | Содержимое до замены, отправленное провайдеру содержимое, итоговый ответ для CLI, сведения о секретах и необходимые метаданные вызова |
| Обновление | Новый вызов заменяет предыдущий снимок этой сессии; не накапливать и не склеивать историю повторно переданных контекстов |
| Перезапуск | В целевой модели runtime-сессии исчезают; конфигурация, manual mappings/версии и legacy-auto сохраняются; новые process-memory auto mappings исчезают |
| Общий бюджет | 200 МБ учитываемых хранимых данных всех runtime-сессий; это не предел RAM/RSS всего процесса |
| Вытеснение | При превышении удалять целиком наиболее давно неактивные сессии по времени последней активности до достаточного освобождения |
| Исключения | Активную сессию не вытеснять ради бюджета. Единственную оставшуюся сессию не удалять и не обрезать, даже если она одна превышает 200 МБ; дальнейший рост допускается |
| Работающий вызов | Превышение бюджета не прерывает запрос/стрим и не обрезает его содержимое; частичное сохранение ради лимита недопустимо |
| Существующая история SQLite | Переход не даёт разрешения автоматически удалять ранее сохранённые пользовательские данные; миграция/очистка согласуется отдельно |

Почему: CLI часто повторно передаёт контекст, сохранение каждого вызова дублирует данные. Для чего: показывать актуальный обмен без роста дискового журнала. Как: снимок последнего вызова на сессию и вытеснение целых неактивных сессий по мягкому бюджету. Почему не иначе: усечение повреждает доступный контекст; жёсткий предел ломает большой активный вызов; хранение только в памяти всей конфигурации теряет правила и соответствия при перезапуске.

Точная единица учёта 200 МБ, состав учитываемых копий и разрешение одновременных вызовов одной сессии фиксируются при проектировании реализации. Не вводить дополнительный TTL или иной числовой лимит без отдельного решения.

## 7. Политики подтверждения (Confirmation Modes)

- `auto`: автоматическая генерация псевдонимов на лету без прерывания диалога.
- `confirm-outbound`: интерактивное подтверждение новых адресов только при исходящих запросах к LLM.
- `confirm-inbound`: интерактивное подтверждение новых адресов только при получении результатов выполнения локальных инструментов.
- `confirm-all`: обязательное подтверждение каждого нового адреса в обоих направлениях.
- `smart-hybrid`: единичные новые адреса открывают модальное окно с тайм-аутом 2 секунды (при истечении генерируется авто-псевдоним); пакетный вывод логов маскируется автоматически без окон.

## 8. Стандарты реализации

- Стек библиотек: `fastify`, `@fastify/http-proxy`, `eventsource-parser`, `zod`, `aho-corasick-node`, `better-sqlite3`.
- Архитектурный стиль: строгое следование [engineering-style.md](../engineering-style.md) (OOP First, стрелочные функции, неявный возврат, запрет комментариев в коде, лимит файлов 10–300 строк).
- Private UI-kit доставлен, полный перенос application frontend завершён и опубликован координатором на `8767`; исходники — `ghostvault/frontend/`. `ui-kit/` и `docs/ui-kit/` остаются у архитектора. Общая production/UX-приёмка и публикация private-пакета в registry не объявляются. Владение, пути и доказательства: [roadmap.md](./roadmap.md#полный-перенос-приложения-на-ui-kit-2026-10-26).

## 9. Мониторинг и управление секретами: согласованные требования

Канонические правила взаимодействия и доступности: [frontend-ux-guide.md](./frontend-ux-guide.md). Предметная модель Vault: [vault-and-monitoring.md](./vault-and-monitoring.md). На `8767` опубликован compact/native followup `530f0a2`: короткий первый запуск, возвращённое «CLI → VAULT», без мета-инструкции о чтении hints. Основные настройки: Claude — shell-neutral `NAME=value` без обязательного ключа/PowerShell, OpenAI/Ollama — Base URL без обязательного Python, OpenCode — штатный same-ID `settings.baseURL`; plugin/alias/relay необязательны. Прежние обязательные Console-key/main plugin recipes заменены. Один пример ранее использованной модели не доказывает все families/auxiliary и не назначает новую платную модель/оплату. [Runtime evidence](../.codex/compact-native-runtime-check.json): 51 URL/MIME/SHA PASS, данные/Claude/OpenCode-конфигурация неизменны, cloud 0; auth/CLI/cloud end-to-end заново не выполнялся, source-backed совместимость не выдана за inference. Пользовательская UX-приёмка/full matrix не заявлены.

Последующая коррекция форм `287029b` развёрнута на `8767`: упрощено создание подключения, сохранён точный ввод секретов, объяснены regex/ошибки/последствия действий. Единый подробный контракт — [UX-гайд](./frontend-ux-guide.md#формы-опубликованная-коррекция-2026-10-27); [runtime evidence](../.codex/forms-clarity-runtime-check.json) подтверждает 51 URL/SHA/MIME и неизменность данных/OpenCode. All-browser/user UX acceptance не заявлены; кеш причиной жалобы не установлен.

Подробные клиентские границы и актуальный источник — [UX-гайд](./frontend-ux-guide.md#конкретные-инструкции-клиентов). Normal pointer текущего «Как подключить» прошёл frontend probe; это не объявляет исправленным общее историческое hint-neighbor наблюдение автора kit. Неизвестный Go/custom клиент не объявлен готовым.

Четыре базовых раздела: «Обзор» / «Подключения» / «Правила» / «Секреты»; при переносе также мигрированы диагностический инспектор и технические события. Создание относится к контексту своего раздела, не к общему header. После отклонения первоначального сценария «Настроить» согласован редактор только выбранного подключения на текущей странице с сохранением рабочего места; каталог остаётся намеренным переходом. Полный frontend-перенос завершён, но соответствие всей матрице UX-требований и пользовательская приёмка не объявлены. Канонический контракт — в UX-гайде; он заменяет противоречащую часть первоначального proposal.

- Правила автообнаружения и их добавление — базовые функции простого режима; расширенный режим не требуется.
- Сохранить список сессий и удобную область диалога. Показывать полный доступный контекст последнего вызова выбранной сессии, без истории вызовов: system, сообщения с ролями, tool calls/results и связи/ID при наличии.
- Общий переключатель меняет весь показанный запрос: содержимое со стороны CLI до замены / содержимое, отправленное провайдеру после защиты. Итоговый ответ для CLI после восстановления показан отдельно. Подписи и hints явно различают CLI → GhostVault → провайдер и обратный путь.
- Отображение зависит от известных структур API. Неизвестные/нетекстовые блоки не исчезают: тип блока и раскрываемый сохранённый JSON. Не обещать универсальное распознавание, внутренний контекст модели или отсутствующий сырой upstream-ответ. Текущий `request.body` может быть уже изменён `beforeOutboundRequest`; это обозначается в интерфейсе.
- Уникальные секреты и счётчики относятся только к последнему выбранному вызову. `DB_HOST (3)` означает три вхождения в отправленном содержимом с учётом представлений; восстановление ответа учитывается отдельно. Текущий `interceptedSecrets.count = 1` не доказывает число вхождений и не может использоваться как точное число замен без отдельного подсчёта.
- Неоднозначные действия имеют подробные доступные hints; основная подпись понятна без hover. Подсказки подстановок доступны в мониторинге, включая JSON/URL/Base64-представления. Правила hover/focus/touch, закрепления и прокрутки определены UX-гайдом.

Почему: сокращённая лента теряет контекст и смешивает стороны обмена. Для чего: пользователь проверяет реально сохранённое отправленное содержимое и результат защиты. Как: один вызов, явные направления, полный доступный контекст и раскрытие деталей по месту. Почему не иначе: склейка разных вызовов и реконструкция недостающих данных создают ложное представление о передаче секретов.

## 10. Экспорт конфигурации

- Экспорт доступен для отдельной настройки/записи, логической группы и всей конфигурации одним файлом; единый машиночитаемый версионированный формат и явный охват. Конкретная схема определяется при реализации.
- Полный экспорт включает ручные/автообнаруженные соответствия с необходимыми реальными значениями, правила, подключения/маршруты, параметры прокси и хуков, остальные необходимые настройки. Скрытие значения в UI не меняет полноту файла.
- Runtime-диалоги не входят в экспорт настроек. До скачивания понятно указаны охват и наличие реальных секретных значений; детали взаимодействия — в UX-гайде.
- Импорт не запрошен и в текущую задачу не входит. Реализован JSON-экспорт версии 1; схема и ограничения программных хуков — [контракт реализации](ux-redesign-implementation.md). Это не полная резервная копия всех данных приложения.

Почему: переносимая конфигурация нужна на уровне одного объекта и всего проекта. Для чего: сохранить полные настройки без ручного переписывания. Как: экспорт выбранного охвата с версией и явным составом. Почему не иначе: файл с масками вместо необходимых реальных значений неполон, а runtime-трафик не является настройкой.
