Ниже сохранены исторические договорённости; в части навигации, форм соединения, инструкций и экспорта актуален указанный документ.


Канонические требования к UX/UI GhostVault. Область: frontend админки. Статус: продуктовые договорённости; наличие требования не означает его реализацию. Архитектура и протоколы: [master-spec.md](./master-spec.md); оформление документации: [documentation-style.md](../documentation-style.md).

Этот документ определяет актуальные правила интерфейса при расхождениях со старыми описаниями мониторинга и отчётами. Изменение хранения, API, фильтрации и конфигурации CLI требует отдельной задачи; UX-гайд такие изменения не разрешает.

## Навигация и контекстные действия

Первоначальная [схема](../.codex/ux-navigation-proposal.md) была одобрена, но пользователь отклонил реализованный переход от «Настроить» одного подключения ко всему каталогу. Требования ниже сохраняют последующую контекстную коррекцию и заменяют противоречащую часть proposal.

Текущий статус `ui-kit-full-migration-20261026`: полный перенос frontend ЗАВЕРШЁН И РАЗВЁРНУТ на `8767`; все 6 разделов, 13 компонентов, 9 SVG. Исходники — `ghostvault/frontend/`, generated `public/` исключён из VCS, локальная сборка без CDN. [Владелец сообщил](../.codex/ui-kit-migration-status.md) PASS изолированного Chromium smoke и чистого source-only setup → build → check; [координатор подтвердил](../.codex/ui-kit-migration-runtime-check.json) 51 live URL по HTTP 200/MIME/SHA. Пользовательская UX-приёмка, IME/AT/CSP и полная матрица не объявлены пройденными; реализация не означает автоматического подтверждения каждого требования этого гайда.

| Раздел простого режима | Основная ответственность |
|---|---|
| Обзор | Все сохранённые перенаправления и удобная область последних вызовов выбранных сессий |
| Подключения | Просмотр, создание и настройка перенаправлений в контексте конкретного подключения |
| Правила | Просмотр и создание правил, управление существующими правилами в рамках доступного контракта |
| Секреты | Ручные и автообнаруженные записи; действия над записью рядом с ней |

Создание принадлежит контексту своего раздела; общие кнопки создания секретов, правил и подключений в header не размещать. Общий header содержит навигацию и общие функции приложения. На Обзоре сохранённая конфигурация, наблюдаемый трафик и последний доступный результат обозначаются отдельно: наличие URL или доступность локального шлюза не доказывают доступ к модели. Первоначальная схема остаётся в proposal с учётом следующей обязательной коррекции:

- Действие над конкретным объектом сохраняет рабочий контекст и открывает именно этот объект; не заставляет искать или выбирать его повторно.
- «Как подключить» открывает на текущей странице инструкции ТОЛЬКО выбранного сервиса. Необязательное изменение upstream отделено от чтения/копирования инструкции. Переход к общему списку или форма всех подключений вместо выбранного недопустимы.
- Сохранение, отмена и закрытие сохраняют исходную страницу, выбранную сессию и положение прокрутки; при завершении фокус возвращается к вызвавшей действие кнопке.
- Периодический опрос/обновление данных не сбрасывает открытый редактор и его несохранённый черновик; повторная выборка каталога не подменяет выбранное подключение.
- «Подключения» остаётся каталогом для намеренного перехода через навигацию. Действие у строки открывает тот же контекст выбранного сервиса, без повторного выбора.
- Подключения на desktop-Обзоре и в каталоге показывать компактными, легко сравнимыми строками. Большие вертикальные карточки с повторяющимися объяснениями и формами не должны вытеснять список и диалоги. Длинные детали раскрывать по месту; мобильная адаптация сохраняет компактность и доступность действий без гигантских повторённых форм.

Почему: общие действия вне контекста скрывают основные функции, переход от выбранного подключения ко всему каталогу заставляет повторять выбор, крупные карточки мешают быстро просмотреть даже небольшой список. Для чего: новичок управляет нужным объектом без потери диалога и отличает настройку от факта работы. Как: четыре страницы, компактные строки, раскрытие деталей по месту, фокусированный диалог конкретного подключения и достоверные состояния. Почему не иначе: глобальное «Добавить» неоднозначно, лишняя навигация теряет рабочее место, повторённые формы создают лишнюю прокрутку, зелёный индикатор по наличию URL создаёт ложную уверенность.

## Первый запуск и подключение (2026-10-27)

Коррекция пользователя после аудита (2026-10-28): блок «Подключение в три шага» удалить целиком. Дословно: «вместо того чтобы исключить вообще эти три шага с интерфейса, ты почему-то подумал что проблема в его наполнении. я считаю это нужно убрать.» Это требование к дальнейшему изменению, не утверждение о выполненной реализации. Переписывание шагов или добавление им прогресса не выполняет решение. Другие предложения [пересмотренного аудита](frontend-ux-audit.md) остаются предложениями; пользователь ещё не принял их.

Почему: пользователь отверг необходимость самого учебного блока. Для чего: освободить рабочий интерфейс от лишнего обучения. Как: удалить блок и зависимый показ; конкретные инструкции подключения остаются доступны по месту. Почему не иначе: более короткий текст или полноценный мастер сохранят отвергнутый элемент.

История реализации: `530f0a2` опубликована на `8767` (2026-10-28), на тот момент 3 кратких шага были сохранены. Инструкции выбранного сервиса открываются через «Как подключить», копирование не сохраняет настройки, редактирование upstream отдельно и необязательно. Дополнительные технические сведения раскрываются через «Показать диагностику»; мета-инструкция о чтении hints убрана. Наличие шагов в этой версии не является требованием сохранить их.

| Видимая подпись | Смысл |
|---|---|
| CLI → VAULT | Локальный адрес подключения приложения к GhostVault; конкретный способ настройки зависит от клиента |
| Куда уйдёт запрос | Сохранённый адрес сервиса; сам URL не подтверждает доступность модели |
| Последний запрос | Наблюдаемый результат либо явное отсутствие данных, не общий статус готовности |
| Готовый вариант | Предустановленный сервис, не доказательство уже настроенного клиента |

Подпись «CLI → VAULT» возвращена для адреса приложения; дополнительные объяснения раскрывают смысл направления. Shared hint открывается hover/focus самого действия, без соседнего Info. Прошлая отдельная Info-механика была реализацией, а не пожеланием пользователя.

Прежняя обязательная main plugin/Console-key схема заменена компактными инструкциями ниже. Для OpenCode основной пример — штатная настройка той же model ID; plugin/alias/relay остаются альтернативой. Инструкция не назначает пользователю новую платную модель или оплату.

Предел доказательств: [focused evidence владельца](../.codex/connection-instructions-compact-all-state.json) и [runtime координатора](../.codex/compact-native-runtime-check.json): 51 URL/MIME/SHA PASS, данные/Claude/OpenCode-конфигурация неизменны, cloud 0. Новые auth/CLI/cloud end-to-end не проверялись. Обычный pointer-сценарий текущего «Как подключить» прошёл frontend probe; историческое общее hint-neighbor наблюдение автора kit этим не объявляется исправленным. Пользовательская UX-приёмка/full matrix не заявлены.

### Конкретные инструкции клиентов

Актуальный источник — [compact/native state владельца](../.codex/connection-instructions-compact-all-state.json), опубликованный как `530f0a2`; он заменяет обязательность прежних recipes `13db02e`/`4ae6bf7`. Полные команды здесь не дублируются.

| Клиент / путь | Область инструкции и ограничения |
|---|---|
| Claude | Shell-neutral `NAME=value` для выбранного подключения; обязательные PowerShell, новый API key и Console billing не навязываются. Это описание настройки, не доказательство всех auth/subscription-путей |
| OpenAI / Ollama | Base URL выбранного подключения без обязательного Python/SDK. Настройка адреса не запускает сервер/модели и не доказывает их готовность |
| OpenCode | Штатный `settings.baseURL` модели с той же model ID — основной пример; plugin/alias/relay необязательны. Пример относится к одной ранее использовавшейся модели, не доказывает все families/auxiliary и не назначает новую платную модель/оплату |
| Go / custom с неизвестным клиентом | Готовность подключения не утверждается без конкретной клиентской инструкции |

Source-backed совместимость и copy/AST/изолированное wiring не являются выполненным inference или новым Claude/OAuth end-to-end. Публикация инструкции не означает её применения к установленному клиенту; внешние конфигурации остались неизменны. Доказательства и ограничения — выше, без повторного запуска клиентов/облака.

## Формы: опубликованная коррекция (2026-10-27)

`ux-forms-clarity-20261027` развёрнут на `8767`, commit `287029b`. Показаны локальные ошибки и последствия действий; текст объясняет существующий контракт, не обещает отсутствующие backend-гарантии.

| Форма | Контракт ввода |
|---|---|
| Подключение | Обязателен только upstream URL; name/prefix предлагаются автоматически с ручным override; адрес виден до сохранения |
| Секрет | Точные key/value/description без scrub/trim; существующий key read-only; при создании UI проверяет дубликат, не обещая атомарную защиту от конкурирующей записи |
| Правило | Вводится regex source без `/…/` и flags; поиск использует `gi`, полное совпадение, затем trim найденного значения и длину >3; type по умолчанию `custom`. Trim совпадения автообнаружения не означает trim ручного секрета |

Почему: лишние обязательные поля и скрытые преобразования затрудняют настройку и меняют данные. Для чего: сохранить точный ввод и объяснить фактическое действие. Как: предложенные значения с override/preview, явные ограничения regex и локальная обратная связь. Почему не иначе: scrub/trim может изменить секрет, а UI duplicate guard не заменяет backend concurrency contract.

[Focused isolated browser evidence](../.codex/ux-forms-clarity-state.json) — по владельцу; [live runtime](../.codex/forms-clarity-runtime-check.json) — координатор: 51 URL/SHA/MIME PASS, данные и OpenCode-конфигурация неизменны, cloud 0. All-browser и пользовательская UX-приёмка не заявлены. Кеш причиной жалобы не установлен.

## Основания решений

| Решение | Почему | Для чего | Как | Почему не иначе |
|---|---|---|---|---|
| Подробные подсказки | Короткая подпись не объясняет область действия и последствия | Предсказуемое управление без догадок | Видимая подпись и критический смысл; подробный доступный hint | Один hover недоступен на touch и скрывает важные последствия |
| Явные стороны обмена | «Запрос», «ответ», «оригинал» неоднозначны при работе прокси | Различать данные до маскирования и после восстановления | Понятные подписи; точные направления CLI → GhostVault → провайдер раскрываются в контексте/hints/диагностике | «Контекст модели» обещает сведения, которых шлюз не имеет |
| Последний вызов сессии | CLI повторно отправляет историю, лента вызовов дублирует сообщения | Видеть актуальное содержимое и актуальные секреты | Последний вызов выбранной сессии, без истории вызовов | Сумма повторно отправленной истории искажает диалог и счётчики |
| Бюджет данных сессий | Полные контексты нескольких сессий накапливают большой объём данных | Ограничивать накопление без повреждения текущего диалога | Политика памяти и вытеснения целых неактивных сессий по master-spec, §6.2 | Обрезка разрушает контекст; жёсткий предел прерывает большие запросы и стримы; размер данных не равен RSS процесса |
| Правила в простом режиме | Добавление правил — повседневная задача | Управлять автообнаружением без поиска расширенных функций | Доступ к правилам и их созданию в обоих режимах | Скрытие правил за расширенным режимом мешает основному сценарию |
| Экспорт настроек | Пользователю нужны переносимые настройки на разных уровнях | Сохранить отдельный объект, группу или всю конфигурацию | Единый вход экспорта, явный охват, версия формата | Экспорт только видимых значений или подстановок может сделать конфигурацию невосстановимой |

## Подписи, действия и подсказки

- Любая неоднозначная кнопка, настройка или переключатель имеет подробный hint. Он отвечает: что делает; к какой стороне обмена относится; к какому объекту и области применяется; что сохраняется локально или передаётся; какие ограничения действуют; как затрагивает реальные секреты и подстановки.
- Основная подпись обозначает действие и объект. Критически нужный смысл виден без hover: направление, область действия, сохранение/передача реальных значений, необратимое последствие, если оно существует. Hint дополняет подпись, не заменяет её.
- Общий шаблон hint: «Действие → объект/область → сохранение/передача → влияние на секреты → ограничения». Неприменимые части не заполняются искусственно.
- Подсказки используют один общий компонент. По умолчанию hover/focus самого объясняемого элемента открывает hint; отдельный оторванный значок «?» не заменяет этот триггер. Указатель может перейти внутрь панели без закрытия.
- Панель привязана к своему триггеру: предпочтительно над ним, с адаптивным смещением/сменой стороны у границ viewport. Фиксированный угол экрана вместо привязки к элементу недопустим. Нет шаблонного жирного заголовка «Подробности»; содержание сразу объясняет конкретный элемент, а заголовок при необходимости предметный.
- Закрепление — F1, удержанием на touch или включённой опциональной кнопкой внутри панели; обычный click/tap выполняет основное действие, а не только открывает hint. Соседнего Info нет. Escape, кнопка закрытия или клик вне закрывают панель; отсутствие кнопки закрепления не удаляет возможность чтения/закрытия pinned hint.
- В контракте kit кнопка закрепления сохранена одной shared-реализацией, её показ опционален и по умолчанию выключен; true включает. Точные props/attributes/defaults — [контракт автора kit](./ui-kit/components/catalog.md) и [механика](./ui-kit/interaction/overlays.md), не пользовательский технический API. Наличие API само по себе не доказывает live-поведение или UX-приёмку и не расширяет focused Chromium доказательства до physical mobile/AT/full matrix.
- Закреплённая панель допускает выделение и копирование текста. Длинное содержимое прокручивается; ширина и высота ограничены viewport. Панель не обрезается контейнерами с `overflow`; общий overlay/portal-слой сохраняет привязку к триггеру, а не фиксирует панель в углу.
- Триггер доступен с клавиатуры и имеет понятное доступное имя. Подсказка связана с ним через `aria-describedby`; интерактивная закреплённая панель обозначается как popover/dialog с именем и состоянием `aria-expanded`. После закрытия с клавиатуры фокус возвращается к триггеру.
- Ввод и фокус не сбрасываются при обновлении данных. Key/value/description секрета не подвергаются скрытому scrub/trim; каретка и выделение сохраняются при редактировании. Ошибка объясняется локально, а не исправляется молчаливой подменой ввода. Автообновление не прерывает чтение и закреплённые подсказки.

Почему: оторванный значок и панель в углу разрывают связь объяснения с действием. Для чего: читать нюансы на месте и сохранять предсказуемость кнопок. Как: hover/focus реального элемента, привязанная панель и отдельная явная механика закрепления без перехвата primary action. Почему не иначе: первый клик только ради hint ломает обычную работу, общий заголовок не добавляет смысла, фиксированная позиция заставляет искать объяснение вдали от элемента.

## Единая терминология данных

Таблица ниже — техническая карта смыслов, не обязательный текст основных кнопок/столбцов первого запуска.

| Подпись | Что показывает | Ограничение |
|---|---|---|
| CLI → GhostVault | Сохранённое содержимое запроса со стороны CLI до маскирования | Текущий `request.body` записан после `beforeOutboundRequest`; это не гарантированная побайтовая копия входящего HTTP |
| GhostVault → провайдер | Сохранённое отправленное тело после маскирования и исходящего хука | `maskedPrompt` не является полным HTTP-дампом и не раскрывает внутреннюю обработку провайдера |
| GhostVault → CLI | Сохранённый итоговый ответ после восстановления и хуков | API может нормализовать структуру; это не сырой upstream-ответ до восстановления |
| Секрет | Зарегистрированное реальное значение | Не смешивать с правилом обнаружения |
| Подстановка | Обозначение вида `$${<DB_HOST>}`, включая варианты кодирования | Не называть реальным значением и не скрывать различие представлений |
| Правило автообнаружения | Условие поиска новых значений | Выключение правила не означает удаления уже зарегистрированных секретов |

Не использовать подписи «фактический внутренний контекст модели», «сырой ответ провайдера», «точный HTTP-запрос», если соответствующие данные не получены и не сохранены. При отсутствии данных показывать ограничение, а не вычисленную реконструкцию под видом оригинала. Подробные оговорки доступны в hint; критическое различие сторон и представлений видно рядом с содержимым.

## Мониторинг выбранной сессии

- Сохранить удобный список сессий и область диалога. Основное содержимое — последний вызов выбранной сессии. Историю последовательности вызовов, переключатель предыдущих вызовов и склейку их контекстов не проектировать. Согласованная политика хранения описана ниже; она ещё не реализована.
- Общий переключатель запроса: «CLI → GhostVault» / «GhostVault → провайдер». Он меняет представление всего выбранного запроса, а не только последнего пользовательского сообщения. Область ответа подписана отдельно: «GhostVault → CLI · после восстановления».
- Показывать весь доступный контекст последнего вызова: системные инструкции, сообщения с ролями, вызовы инструментов, результаты инструментов и их связи/идентификаторы, если они присутствуют в сохранённых данных. Это контекст переданного запроса, не гарантия полного внутреннего контекста модели.
- Известные блоки имеют читаемое представление. Неизвестный или нетекстовый блок сохраняется в интерфейсе как тип блока с раскрываемой структурой JSON; не заменять его сообщением «содержимого нет». Сохранённая структура доступна для детальной проверки; читаемое представление не должно молча терять поля.
- Подстановки имеют hover/focus-подсказки с ключом, представленным вариантом и соответствующим реальным значением, когда такая связь достоверно доступна. Подсказка доступна в мониторинге, включая кодированные варианты. Если точная связь неизвестна, не угадывать её по похожему имени.
- Список уникальных секретов относится только к последнему показанному вызову. Не суммировать повторённую историю предыдущих вызовов и не смешивать отправку с восстановлением ответа.
- Текущий `interceptedSecrets.count = 1` фиксирует обнаружение секрета в обработанном текстовом поле/потоке, а не число текстовых вхождений. При использовании этих данных числа подписывать «обнаружений в запросе» / «обнаружений в ответе» с объяснением в hint. `DB_HOST (3)` без явного определения счётчика недопустим.
- Целевой смысл `DB_HOST (3)` — три вхождения в отправленном содержимом последнего вызова. Требуется отдельный достоверный подсчёт по сохранённому отправленному запросу с учётом представлений. Не объявлять такой подсчёт числом фактически выполненных замен, если источник данных этого не подтверждает.

## Хранение последних вызовов: согласованное требование, пока не реализовано

Нормативный источник политики — [master-spec.md, §6.2](./master-spec.md#62-данные-последних-вызовов-согласовано-пока-не-реализовано). Здесь определено только отражение в UI: последний доступный вызов на сессию, отсутствие истории вызовов, удаление вытесненной сессии целиком из списка и сохранение активного содержимого без обрезки. Перезапуск очищает runtime-сессии, но не настройки и соответствия секретов. Не выдавать бюджет данных за жёсткий предел RAM процесса; данные старой SQLite самостоятельно не удалять.

## Простой режим и настройки секретов

- Ручные секреты, автообнаруженные секреты, правила и создание правил доступны в простом и расширенном режимах. Переключение режима не закрывает выбранную вкладку правил и не сбрасывает незавершённый ввод.
- Обозначать различия: ручная запись задаёт конкретное значение; правило ищет новые значения; автообнаруженная запись уже участвует в замене; Promote переводит запись в ручное управление.
- Подсказки управления правилами объясняют область применения и последствия: выключение/удаление правила останавливает новый поиск; уже найденные секреты сохраняются. Удалённый секрет может обнаружиться повторно при активном правиле.

## Экспорт настроек: обязательное требование, пока не реализовано

- Экспорт доступен у каждой настройки/настроечного объекта и логической группы; полный экспорт охватывает все настройки. Во всех местах используется единое действие «Экспорт» и один понятный вход выбора охвата: «Эта настройка» / «Эта группа» / «Все настройки».
- Экспортируется полный настроечный объект выбранного охвата, включая реальные значения там, где без них нельзя восстановить конфигурацию. Скрытие значения точками в UI не должно превращать экспорт в невосстановимый набор масок.
- До скачивания рядом с действием явно указаны охват и наличие реальных секретных значений в файле. Подробный hint объясняет состав, локальное создание файла и влияние на секреты. Не вводить навязчивое дополнительное подтверждение для обычного экспорта и не отправлять файл стороннему сервису.
- Один машиночитаемый формат для всех охватов: стабильный идентификатор формата, числовая версия схемы, явный охват и полные значения выбранных настроек. Конкретная схема согласуется при реализации; версия обязательна с первого выпуска. Расширенные и скрытые настройочные поля нельзя молча пропускать из полного экспорта.
- Состав полного экспорта определён [master-spec.md, §10](./master-spec.md#10-экспорт-конфигурации-согласовано-пока-не-реализовано). Runtime-диалоги не входят; экспорт настроек не обозначать резервной копией всех данных приложения.
- Импорт не запрошен и не входит в задачу. Не добавлять импорт, миграции, новые API или сам экспорт на основании фиксации этого требования.

## Критерии проверки будущей реализации

| Область | Проверка |
|---|---|
| Hint | Hover/focus реального элемента без обязательного отдельного «?»; панель рядом с триггером, предпочтительно сверху, viewport fallback; нет общего «Подробности»; закрепление/копирование/прокрутка/Escape/клик вне/возврат фокуса; первый клик выполняет основное действие |
| Ввод | Вставка в середину, выделение/замена, точность key/value/description без scrub/trim, existing key read-only, create duplicate guard; отсутствие прыжка каретки и тихой подмены ввода |
| Режимы | Правила и их создание доступны в простом режиме; переключение режима сохраняет рабочее состояние |
| Контекстное действие | «Как подключить» на Обзоре и в каталоге открывает только выбранный сервис; copy не сохраняет настройки; optional upstream-редактирование отделено; закрытие/сохранение сохраняют контекст и возвращают фокус; опрос не сбрасывает черновик |
| Плотность подключений | Desktop-списки компактны и сравнимы; длинные детали раскрываются; mobile не превращается в набор больших повторённых форм |
| Стороны | Запрос до/после маскирования различим; итоговый ответ не назван сырым upstream; недоступные данные обозначены |
| Последний вызов | Изоляция выбранной сессии, полный доступный контекст одного последнего вызова, отсутствие склейки предыдущих вызовов |
| Бюджет сессий | UI соответствует master-spec, §6.2: вытесненные неактивные сессии удаляются целиком; активное содержимое не обрезается; исключения мягкого бюджета и потеря runtime-сессий после рестарта объяснены |
| Структуры | Роли, system, tools/results и неизвестные блоки не теряются; специальные символы отображаются как текст |
| Секреты | Уникальные ключи выбранного вызова, объяснённая единица счётчика, разделение направлений, подсказки кодированных подстановок |
| Экспорт | Единый вход, отдельная настройка/группа/все, версия, полный объект, реальные необходимые значения, явное содержимое файла; импорт отсутствует |
