# GhostVault Vault и мониторинг последних вызовов

Предметная модель секретов и состояние мониторинга на 2026-10-25. Норматив хранения и экспорта: [master-spec.md](./master-spec.md); канонический UX: [frontend-ux-guide.md](./frontend-ux-guide.md). Согласованная новая модель мониторинга пока не реализована; старые описания Auto Vault с сессионным TTL и постоянного журнала вызовов не являются актуальными требованиями.

## Секреты и правила

| Объект | Назначение | Жизненный цикл |
|---|---|---|
| Ручной секрет | Заданное пользователем точное значение и alias | Персистентен; управляется вручную; приоритет перед автообнаружением |
| Правило автообнаружения | Regex для поиска новых значений в целевых полях исходящего запроса | Персистентно; включается/выключается и удаляется независимо от найденных секретов |
| Автообнаруженный секрет | Конкретное найденное значение и alias | Уже участвует в маскировании; персистентен; сессионный TTL не предусмотрен |
| Promote | Перевод автообнаруженной записи в ручное управление | Сохраняет значение и alias; переименование при переводе не заявляется |
| Представление секрета | Raw/URL/Base64/JSON-вариант известного значения | Отдельный alias различающихся представлений обеспечивает точное обратное восстановление; форматы — в master-spec |

- Правило не является секретом. Выключение/удаление правила прекращает новый поиск, но сохраняет найденные соответствия. Удалённый секрет может обнаружиться повторно, если правило осталось включено.
- Удаление или вытеснение сессии мониторинга не удаляет секреты, правила и маршруты. Соответствия общие для экземпляра, а не автоматически изолированные по `sessionId`.
- Автообнаружение выполняется на исходящих целевых текстовых полях после приоритетной обработки ручных значений. Новый найденный секрет маскируется уже в этом запросе. На ответе выполняется восстановление известных подстановок; новый произвольный секрет из ответа сам по себе не регистрируется.
- Управление правилами относится к простому режиму. Это согласованное UX-требование; текущий интерфейс ещё требует обновления.

Почему: правило описывает класс значений, а соответствие нужно для последующих замен и восстановления. Для чего: не терять защиту после перезапуска или очистки мониторинга. Как: отдельно хранить конфигурацию/соответствия и runtime-снимки сессий. Почему не иначе: привязка Auto Vault к времени жизни диалога уничтожает известные соответствия при удалении его отображения.

## Мониторинг: текущая реализация и согласованная цель

| Область | Сейчас | Согласованная цель; пока не реализована |
|---|---|---|
| Хранение | Последовательность вызовов записывается в SQLite; есть память процесса | Только последний вызов каждой сессии в памяти, без дискового журнала трафика |
| Диалог | Выжимка последнего user-сообщения и ответа для каждого вызова | Полный доступный контекст последнего вызова выбранной сессии |
| Представления | Мониторинг не предоставляет все возможности расширенного инспектора | Общий переключатель содержимого до/после защиты; отдельно итоговый ответ для CLI |
| Секреты | Данные обнаружений содержат направления и `count`, не равный числу вхождений | Уникальные ключи последнего вызова; точные вхождения в отправленном содержимом; восстановление отдельно |
| Неизвестный блок | Читаемое представление может пропустить содержимое | Видимый тип и раскрываемый сохранённый JSON без угадывания структуры |
| Бюджет | Согласованный механизм 200 МБ ещё не реализован | Политика вытеснения и исключения определены только в master-spec, §6.2 |
| Экспорт | Полный экспорт настроек ещё не реализован | Настройка/группа/всё по master-spec, §10; runtime-снимки не экспортируются как настройки |

Содержимое «до защиты» может быть уже изменено `beforeOutboundRequest`; сохранённое отправленное тело не является полным HTTP-дампом. Итоговый ответ записан после восстановления/хуков и может нормализоваться API: его нельзя выдавать за сырой upstream. Последний запрос также не гарантирует полный внутренний контекст провайдера, если клиент использовал ссылки на ранее сохранённое состояние или сокращение истории.

## Ожидающие исправления интерфейса

| Дефект | Ожидаемое поведение |
|---|---|
| Каретка названия секрета прыгает в конец после нормализации input | Ввод в середине, выделение/замена и удаление символов сохраняют корректную позицию и выделение |
| Подсказки подстановок отсутствуют в мониторинге | Общий доступный компонент hint/popup; поддержка вариантов JSON/URL/Base64 при достоверной связи с секретом |
| Системные инструкции и часть tool calls/results теряются в читаемом виде | Полный доступный контекст, роли/типы, связи инструментов при наличии, fallback неизвестных блоков |
| Правила скрыты за расширенным режимом | Просмотр и добавление правил в обоих режимах |

Эта фиксация не изменяет UI, API, SQLite или пользовательские данные. Порядок реализации и проверки: [roadmap.md](./roadmap.md). Подробные требования подсказок и визуального взаимодействия не дублируются здесь; источник — UX-гайд.
