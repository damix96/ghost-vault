# Техническая инструкция оценщику AGY

Использовать вместе с общим промптом UX/UI-исследования. Организатор подставляет SESSION, OUTPUT и URL. Headless Chrome через Selenium уже запущен и сохраняет состояние между командами. Не генерируй собственный Selenium-скрипт и не закрывай браузер после каждого действия.

Через `run_command` выполни готовый инструмент:

```powershell
& 'D:\tools\anaconda\python.exe' 'E:\projects\aegis-gate\scripts\browser_operator.py' --session 'SESSION' --action screenshot
```

Результат — JSON: `status`, `screenshot`, `cursor`, `url`, при ошибке — `error`. Открой файл из `screenshot` через `read_file` в режиме изображения либо штатный image-viewer AGY. Убедись, что видишь изображение, а не байты/метаданные. Это обязательный шаг компьютерного зрения. Если изображения недоступны, сообщи об ограничении; HTML и DOM не являются заменой.

Агент самостоятельно решает, что исследовать. Ниже доступные операции, не сценарий:

| Действие | Аргументы того же инструмента |
|---|---|
| Клик по видимому тексту | `--action click --target 'ТОЧНЫЙ ТЕКСТ СО СКРИНШОТА'` |
| Наведение | `--action hover --target 'ТОЧНЫЙ ТЕКСТ СО СКРИНШОТА' --wait 1` |
| Клик/наведение по точке | `--action click --x 420 --y 260` либо hover; координаты выбираешь сам по скриншоту |
| Ввод в фокус | `--action type --value 'ВЫМЫШЛЕННЫЕ ДАННЫЕ'` |
| Замена ввода в поле с видимым placeholder | `--action type --target 'PLACEHOLDER' --clear --value 'ВЫМЫШЛЕННЫЕ ДАННЫЕ'` |
| Клавиатура | `--action key --key TAB` либо ENTER, ESCAPE, BACKSPACE, ARROW_DOWN |
| Зажать/отпустить Ctrl | `--action keydown --key CONTROL` / `--action keyup --key CONTROL` |
| Прокрутка под указателем | `--action scroll --x 900 --y 600 --dy 500`; отрицательное dy — вверх |
| Узкий экран | `--action resize --width 390 --height 844` |
| Навигация браузера | `--action back`, `--action forward`, `--action reload` |
| Новый снимок | `--action screenshot --wait 1.5` |
| Закрыть после завершения отчёта | `--action close` |

После каждого значимого действия открой новый скриншот. Не делай серию незрячих кликов и не оценивай результат только по JSON. Открытые формы, введённые значения, cookies, фокус, scroll и удерживаемые клавиши сохраняются до следующей команды. Модификаторы нужно отпускать явно.

Текст цели должен быть реально виден на предыдущем скриншоте; инструмент ищет точное совпадение в текущей видимой области, включая Shadow DOM. Несколько совпадений дают ошибку, а не случайный выбор. Тогда используй самостоятельно выбранные координаты. Не ищи скрытые aria-label/CSS/ID ради обхода непонятности. После прокрутки/resize координаты старого снимка устаревают. PNG обычно не включает курсор: тип приходит отдельным полем, строго под текущим указателем.

Не передавай дополнительные Chrome-флаги, не используй свой webdriver и произвольный JavaScript. Общий помощник предоставляет только мышь, клавиатуру, навигацию, размеры, PNG и тип курсора. Он не открывает окон на экране пользователя. Изменение UI выполняй только через его видимые элементы.

Запиши `OUTPUT/report.md` и `OUTPUT/journey.md`. Все PNG автоматически лежат в `OUTPUT/screenshots/`, журнал — `OUTPUT/actions.jsonl`. В отчёте ссылайся на конкретные снимки. Допустимые файловые записи — эти материалы исследования; не меняй исходники продукта, настройки компьютера или файлы клиента. Прогоны других оценщиков не читать.

Почему один браузер: новый webdriver на каждую команду теряет рабочее состояние и не позволяет исследовать последовательность взаимодействий. Почему готовый помощник: оценщик занимается опытом пользователя, а не поиском Selenium-API и отладкой своих скриптов. Отличается только инструмент вызова/просмотра картинки; браузерное поведение у AGY и Codex одинаковое.
