# Отображение зашифрованных переменных

Норматив от 2026-11-07. Источник: пользователь: «зачем скрывать от самого пользователя? пусть это будет галочкой в настройках. \"скрывать зашифрованые данные в интерфейсе\"»; уточнение: «не будешь все данные скрывать, а только секретные зашифрованые». Заменяет прежнее обязательное скрытие оригиналов в локальной панели. Дефолт выключен — решение координатора, сообщённое пользователю. Последующее требование обратимого шифрования записано ниже отдельно.

| Поверхность | Контракт |
|---|---|
| Создание | Одна кнопка «Добавить переменную», одна форма, checkbox «Шифровать». Обычная запись использует прежний POST; зашифрованная — `isSecret:true,operation:create|update`. |
| Зашифрованная запись | Уточнение пользователя 2026-11-07 отменяет введённый координатором запрет обратного преобразования: checkbox «Шифровать» включается и выключается. Снятие сохраняет текущее точное значение без обязательного повторного ввода, имя/подстановка/настройка замены сохраняются. Поправка установлена; прежняя приёмка одностороннего варианта дополнена новой. |
| Настройки интерфейса | `ghostvault.hide-encrypted` в localStorage конкретного браузера, default false. При true скрываются известные текущие/архивные/удалённые зашифрованные значения и их представления; имена, шаблоны, обычные значения и окружающий текст остаются. |
| Отображение original | Явные same-origin POST `/api/interface/vault`, `/api/interface/sessions/:id` с `Origin` и `X-GhostVault-Display: original`. Ответ `Cache-Control: no-store`. SSE `/api/interface/events` требует `Sec-Fetch-Site: same-origin`. Общий AdminAccess сохраняется. |
| Существующие API | `/api/vault`, `/api/sessions`, `/api/events`, экспорт сохраняют проекцию без защищённых оригиналов. MCP не получает новые value-bearing tools. |
| RAM | Последний вызов хранит приватный оригинал отдельно от безопасной проекции; различающиеся копии включены в прежний мягкий бюджет. Удаление/вытеснение/рестарт освобождает обе. Исходное значение не восстанавливается из текущей записи Vault: изменение значения не переписывает прошлый запрос. |
| Трансформации | Трафик CLI→модель маскируется как прежде; модель→CLI восстанавливается как прежде, включая цитаты и код. Переключатель не затрагивает payload/hooks/DPAPI. |
| Подсказки | Соответствие называется «Значение / Шаблон»: наличие шаблона само по себе не доказывает, что именно это вхождение заменило оригинал. Подтверждённые восстановления используют сохранённые before/after, при скрытии подписаны «Значение скрыто». |
| Ответ | Роль «Ассистент», отметка восстановления отдельно; у фрагмента есть «Показать полный ответ». Нормализованная копия ответа не дублирует оригинальную. |
| MCP каталог | Публичная строка `{name,description?,source}` без дублирующего token; instructions задают `$${<NAME>}`. Внутренний каталог и HTTP receipt ввода сохраняют собственные совместимые формы. |

Причина разделения: шифрование на диске не означает запрет владельцу видеть собственные значения. Отдельные интерфейсные маршруты сохраняют прежние безопасные API и исключают случайную публикацию оригиналов модельному инструменту; они не обещают изоляцию от программ того же пользователя. Общий глобальный reveal-переключатель менял бы поведение всех клиентов, поэтому выбор хранится в браузере. При включении скрытия очищаются уже загруженные контексты/подсказки и переподключается канал событий; это не отзывает ранее скопированный текст.

Проверки: `test-interface-display`, `scripts/test-interface-ui.mjs`; смежные MCP/retention/projection/stream suites. Фикстуры синтетические, без пользовательской БД.

## Короткие подписи и группировка

Пользователь запросил пустой preview с многоточием и заполненный с именем. UI использует действующий протокольный синтаксис: `$${<...>}` и `$${<VALUE>}`; ошибки имени остаются отдельной валидацией. Поясняющий абзац настройки скрытия удалён как повторяющий название и перечисляющий несвязанные механизмы. Это изменение текста, не правил шифрования/маскирования.

Пользовательский пример списка: FIX_123_321/FIX_123_333 объединяются в FIX_123, FIX_232_333/FIX_232_553 в FIX_232; FIX_121_222 и FIX_456_455 остаются полными одиночными строками. Auto-список сравнивает часть key до последнего `_` с непустыми сторонами; группа появляется при двух и более членах полного dataset. Длина последней части произвольна. Детерминированный порядок координатора: группы/дети по полному имени, затем одиночные по key. Группы исходно закрыты, вложенного родителя FIX нет. Это визуальная группировка текущих имён, не восстановление происхождения правила; данные/aliases не меняются. Эвристика фиксированной длины и новое metadata отвергнуты как ненужные этому поведению.

Поиск сохраняет membership полного dataset, показывает matched/total и временно раскрывает группы; очистка возвращает пользовательское состояние. Ctrl-переход раскрывает родителя. Одночленная группа после удаления/переноса становится полной строкой. Existing actions/privacy/focus guards сохраняются; состояние раскрытия только RAM. Названия вкладок ещё не выбраны пользователем и не менялись.

Copy/grouping установлены UI-only на live8767 без перезапуска/изменения БД: public index SHA256 `8A8E1779EFDC197D512CBE20D726B04C44C76D74A86C08B34273883AFFCE1A45`. Это новая статическая сборка поверх установленного release28b63d5f1697; прежний tarball больше не описывает public byte-for-byte. Исходные assets сохранены для открытых вкладок, index заменён после копирования новых assets. Проверены owner pure/browser8cases, source hashes, отдача нового HTML/assets и отсутствие ошибок загрузки. Root дополнительных screenshots группировки не делал. ## Обратимое шифрование

Источник: пользователь отклонил «Отключение шифрования пока не поддерживается»: «а во вторых что значит отключение шифрования не поддерживается?? сфигали????». Прежний запрет demotion был решением координатора, а не требованием пользователя. Это дополнение отменяет его в предыдущих контрактах. Шифрование управляется одной галочкой; снятие не требует заново вводить сохранённое значение. Длинные пояснения о request snapshots/сохранении aliases/невозможности отключения в форме удаляются; пользовательские свойства операции выражены самим полем/галочкой.

| Граница | Согласовано root/backend, task variable-encryption-toggle-20261107 |
|---|---|
| PATCH `/api/vault/secret/:key` | Strict union прежнего `{name}` и `{isSecret:boolean,realValue?:string,description?:string}`. Отсутствующий realValue сохраняет точное текущее значение; переданный должен быть непустым well-formedUTF16. Отсутствующее описание сохраняет, пустое очищает. Нет смешанного rename+update. |
| Атомарность | Снятие/включение шифрования и опциональное новое значение/описание — одна операция; выбранная current manual запись и связанные архивы согласованы. Ошибка decrypt/provider/SQL не оставляет частичный переход. Имя, aliases, maskInAi и уже начатые request snapshots сохраняются. |
| POST совместимость | true требует operation:create/update. false поддерживает необязательный operation с теми же проверками существования; false без operation — ordinary upsert. Отсутствующий flag сохраняет существующую protection; operation без flag400. Editor revision не добавляется. |
| Ответы |200 `{success:true,secret,notice?}`;404 отсутствующая fixed/только auto;400 invalid input;409 существующий create/конфликт;503 unavailable provider;422 decrypt failure. Notice при committed hygiene failure остаётся успешным сохранением. |
| DTO/экспорт | Protected rows прежние metadata/valueOmitted. После явного снятия current/соответствующие архивные ordinary values/forms точны. Generic redactor не должен повторно заменять их токенами только из-за lifetime remembered history; другие private history/lastCall/settings/hooks boundaries сохраняются. MCP остаётся names-only. |
| Editor | Existing field необязателен, пустой означает «Без изменения». Если preference позволяет original, он доступен в поле; при скрытии поле пустое. PATCH включает realValue только после реального редактирования непустого поля, исключая перезапись/нормализацию current при checkbox-only save. Sensitive draft не сохраняется; lost response допускает GET-only review без replay. |
| SQLite | При открытии убрать старые prevent_demotion triggers, сохранить shape integrity constraints. Это смена правила, не автоматическая конверсия пользовательских записей. |

Причина отдельной atomic PATCH: последовательные toggle и value update могли оставить неверную половину изменения при ошибке между запросами; повторная загрузка original ради checkbox-only save лишняя и могла изменить точные переводы строк. Выборочное сохранение ordinary DTO-полей устраняет повторное скрытие demoted данных, сохраняя остальные приватные поверхности. Реализация, scoped приёмка и live-доставка завершены: [доказательства](interface-privacy-validation.md#обратимое-шифрование-и-группировка).
