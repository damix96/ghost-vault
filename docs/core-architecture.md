# 01. Архитектура ядра и Синглтон-демон

Архитектурная модель GhostVault: разделение на долгоживущий демон пользовательской сессии и тонкие клиентские адаптеры.

## Проблемы изолированных клиентских процессов

Инструменты разработки на базе AI (Claude Code, Antigravity, OpenCode, Cursor, Aider) исполняют вспомогательные процессы (MCP-серверы, скрипты, CLI-утилиты) изолированно:

| Фактор | Механизм ограничения | Последствие для системы |
|---|---|---|
| Независимые процессы на каждый CLI | Каждый терминал поднимает изолированный пул подпроцессов | Конфликты сетевых портов (`EADDRINUSE`), конкурентные блокировки файлов и БД SQLite (`SQLITE_BUSY`), рассинхронизация таблиц секретов |
| Изоляция оконной станции | Флаги `windowsHide: true` и `CREATE_NO_WINDOW (0x08000000)` | Дочерние процессы лишены доступа к интерактивной оконной станции (`winsta0\default`). Графические модальные окна (`ShowDialog`) зависают в памяти без отображения |

## Архитектурное решение: Client-Daemon Singleton Pattern

Вместо запуска изолированных MCP-серверов внутри каждого CLI-клиента инфраструктура разделяется на два компонента:

```
[ CLI 1: Claude Code ] ──► [ micro-mcp ] ──┐
                                            │
[ CLI 2: Antigravity ] ──► [ micro-mcp ] ──┼──► [ GhostVault Singleton Daemon ]
                                            │    • Порт: 127.0.0.1:8765
[ CLI 3: Cursor / IDE ] ─► [ micro-mcp ] ──┘    • Единое хранилище: ~/.ghostvault/vault.db
                                                 • Управление GUI: WPF через schtasks
                                                 • Web Dashboard: http://127.0.0.1:8765/dashboard
```

### 1. GhostVault Singleton Daemon (Сервер-Синглтон)

- **Контекст исполнения:** Запускается один раз в активной интерактивной сессии пользователя (`Session 1`), имея доступ к оконной станции (`winsta0\default`), рабочему столу, экрану, буферу обмена и браузеру.
- **Интерфейсы:** Локальный HTTP, SSE и WebSocket на порту `127.0.0.1:8765`.
- **Функции:**
  - Поддержание транзакционной базы сопоставлений: `Реальное значение <-> $${<NAME>}` в SQLite (режим WAL).
  - Reverse Proxy для API провайдеров моделей: Anthropic (`/v1/messages`), OpenAI (`/v1/chat/completions`).
  - Потоковая модификация SSE-стримов и распаковка аргументов `tool_use`.
  - Запуск модальных окон подтверждения для новых сущностей.
  - Предоставление Web Dashboard на `http://127.0.0.1:8765/dashboard` для аудита и ручного управления переменными.

### 2. micro-mcp (Легковесный клиент-адаптер)

- **Размер и сложность:** Скрипт объемом ~50 строк кода без сторонней логики и рендеринга UI.
- **Функции:**
  - Регистрация в конфигурациях AI-клиентов как стандартный stdio MCP-сервер.
  - Проксирование входящих JSON-RPC вызовов инструментов в GhostVault Singleton Daemon через локальный HTTP.
  - Контроль доступности демона: при отсутствии ответа на порту `8765` инициирует его запуск через Windows Task Scheduler (`schtasks`).

## Точка перехвата трафика (Подключение AI-клиентов)

Маршрутизация запросов AI-клиентов через шлюз настраивается через системные переменные окружения базового URL:

```bash
# Claude Code (Anthropic API):
export ANTHROPIC_BASE_URL="http://127.0.0.1:8765"

# Cursor / OpenCode / Aider (OpenAI API):
export OPENAI_BASE_URL="http://127.0.0.1:8765/v1"
```

### Архитектурный выбор: `BASE_URL` вместо `HTTPS_PROXY`

| Критерий | Переменная `BASE_URL` | Системный `HTTPS_PROXY` |
|---|---|---|
| TLS/SSL сертификаты | Локальный loopback HTTP (`http://127.0.0.1:8765`). Сертификаты не требуются, ошибки проверки trust store исключены | Требуется генерация и добавление самоподписанного корневого CA в доверенные хранилища ОС, Node.js (`NODE_EXTRA_CA_CERTS`) и Python (`SSL_CERT_FILE`) |
| Взаимодействие с EDR/DLP | Локальный HTTP трафик между процессами одного пользователя не триггерит алерты о подмене TLS-сертификатов (MITM) | Инспекция и переподписание внешних TLS-соединений классифицируется защитными средствами как MITM-атака |
| Прозрачность сетевого слоя | Шлюз принимает чистый HTTP, маскирует данные и самостоятельно открывает легитимный HTTPS-сокет во внешний API через системный доверенный пул CA | Прокси должен обрабатывать метод `CONNECT`, реализовывать перехват сессий и поддерживать синхронизацию сертификатов внешних доменов |
