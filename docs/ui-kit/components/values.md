# Значения и преобразования

[Раздел](index.md).

Цель — сохранять смысл данных и исключить связь независимых экземпляров. Строка, показанная пользователю, не всегда является машинным значением.

## Контракт значения

| Вход | Значение по умолчанию |
|---|---|
| `undefined` | Параметр не передан; применять documented default |
| `null` | Явное отсутствие, только если допускает тип |
| `''` | Пустая строка; не автоматически отсутствие |
| `0`, `false` | Полноценные значения; не заменять через truthiness |
| Неполный ввод | Черновой текст; parsing может ещё не дать валидное значение |

Тип/карточка определяет accepted values, optional/null, default, reset и ошибки. Нельзя превращать `0` в placeholder или стирать недоступную option без решения owner.

Частично заполненная форма содержит draft, а не автоматически корректный payload. Неприменимое поле не равно пустому: domain определяет сохранение/исключение его значения при submit. Скрытие control не стирает draft и не подтверждает, что его значение нужно отправить. Результат проверки учитывает только предусмотренные контрактом зависимости и применимость.

Controlled: значение принадлежит consumer; component сообщает предложенное изменение. Uncontrolled: собственный draft/initial определены контрактом. Не переключать ownership случайным появлением `undefined`; смена режима требует явного reset/переинициализации.

## Props и экземпляры

- Входные объекты/arrays принадлежат передавшему их owner; component не мутирует их молча.
- Изменение через новую ссылку или explicit revision определяет контракт. Нельзя одновременно обещать произвольную in-place mutation и проверять только reference equality.
- Мутируемый default создаётся для экземпляра, не хранится общим singleton/prototype значением. Shared config действительно immutable.
- ID экземпляра/записи не зависит от позиции в отсортированном списке.
- Карточка указывает, какие изменения сохраняют draft, какие меняют entity и какой reset их сопровождает.

## Parsing и formatting

Хранить исходный draft отдельно от parsed value и formatted preview. Parse невалидного промежуточного текста не должен автоматически заменять его последним числом/default. Ошибка имеет понятный источник/поле.

Trim допустим для конкретного domain-поля по его контракту. В реальном секрете пробел может быть частью значения; primitive Field не нормализует все строки одинаково. Очистка пользователем даёт явное пустое значение, а не «нет обновления».

Форматирование даты/числа не меняет машинный payload/copy. Значения, для которых JSON/Number уже потерял точность, невозможно восстановить UI: договориться о lossless string/type на границе; не обещать точный original по округлённому значению.

См. [представление](../data/representation.md), [формы](forms.md), [черновики](../interaction/editing.md).

Проверка: `undefined/null/empty/zero/false`, частичный ввод, два экземпляра с default array, in-place mutation, reorder, locale и большое число.
