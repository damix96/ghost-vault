# Область и статус правил

[Раздел](index.md).

Цель kit — уменьшать повторяемую структуру/поведение и цену общего изменения. Количество классов или коротких файлов само по себе успех не доказывает: после изменения общего контракта должны обновляться его потребители, а не копии реализации.

## Статусы

- Действуют [engineering-style](../../../engineering-style.md), глобальные/project AGENTS и [UX](../../frontend-ux-guide.md).
- Это руководство — авторская спецификация kit, подготовленная по поручению пользователя; реализация 0.1.0 отдельно разрешена координатором.
- Kit остаётся в `ui-kit/`. Новое поручение пользователя разрешило полный перенос приложения отдельному `uikit-senoir-expert`; kit owner меняет только `ui-kit/` и `docs/ui-kit/`. Это не передача ему frontend/backend или чужих документов.
- Технический выбор автора и незакрытые support limits записаны в [решениях](../delivery/decisions.md); фактический API — [в каталоге](../components/catalog.md).

## Инженерные ограничения

| Правило | Применение |
|---|---|
| Минимум самописного | Сначала готовый надёжный primitive; свой слой для устойчивого product/API контракта |
| OOP First | Состояние, сеть и lifecycle в классах; stateless helpers не изображают stateful-компонент |
| Arrows/implicit return | Приоритет arrows; `function () {}` и block ради одного `return` запрещены; несколько действий допускают block |
| No-comments | Ручной код без comments/JSDoc; объяснение и контракт — здесь/в типах |
| 10–300/SRP | Делить по ответственности; не минифицировать и не добавлять padding ради числа строк |
| Tailwind/Lucide | Сохранять проектный выбор; это не требование utility-only или отсутствие CSS |

LOC/no-comments проверяются для authored TS/MJS/CSS/HTML; JSON/config не дополняются бессмысленными строками. Generated dist, node_modules и vendor SVG/licenses сохраняют upstream notices и не оцениваются как authored code.

## Слои

Page выбирает композицию и связывает события. Domain определяет product labels, бизнес-валидацию, источник данных и доступные действия. Kit владеет повторяемым представлением, состояниями controls и interaction contract. Vendor обеспечивает готовые primitives. Controller приложения владеет API, concurrency и business side effects.

Зависимости не разворачиваются: primitive не импортирует приложение/Vault/API. Один DOM-участок имеет одного renderer и владельца lifecycle. Совместная файловая система не даёт права править чужой компонент.

Новая потребность оценивается по общему контракту и цене сопровождения. Ни «ноль похожих строк», ни «бесконечно расширяемый API» не являются измеримой универсальной гарантией.
