# Поддержка документации

[Раздел](index.md).

Почему: большой общий текст расходует контекст и скрывает нужный контракт. Цель — найти правило по задаче, не читать всё дерево.

- Файл — одна тема, около 200 строк максимум. При росте делить по реальной ответственности, не по произвольному номеру части.
- Тематическая папка имеет `index.md`: краткие назначения leaf и ссылки на вложенные ветки. Вложенность добавляется только для настоящей группы тем.
- Root index маршрутизирует по роли/задаче; leaf ссылается на свой index и нужные соседние механизмы.
- Общая норма определяется один раз. Другая тема ссылается на неё, не копирует полный текст.
- Норма отличается от rationale, примера, предложения и открытого решения. Назвать источник/owner/version, когда это меняет действие.
- По [documentation-style](../../../documentation-style.md): плотный текст, semantic имена, без emoji; решение объясняет почему/цель/механизм/альтернативу.

## Карточка и пример

Карточка реализованного компонента: назначение/use-not-use, status/version/owner, public import, inputs/defaults/events, states, доступность, ограничения, related recipes. Текущая поверхность — [каталог](../components/catalog.md).

Минимальный пример использует публичный пакет и synthetic data. Показывать success и важный failure/state; не писать второй скрытый контракт в demo. Существование примера не доказывает browser support или UX-приёмку.

Runtime-specific описание указывает применимую версию. При изменении API/default/token обновить связанные примеры, migration note и карточку тем же scope; устаревший пример пометить/удалить.

## Проверка дерева

После move/rename обновить родительский index, входные/обратные ссылки и cross-links. Проверить существование файлов/anchors, достижимость каждого leaf от root, наличие index каждой папки и размеры всех Markdown-файлов. Не оставлять orphan-норму, доступную только через поиск.

Структурная проверка не заменяет проверки фактического поведения. Крупные состояния/evidence остаются в [testing](../delivery/testing.md), а непроверенные решения — в [decisions](../delivery/decisions.md).
