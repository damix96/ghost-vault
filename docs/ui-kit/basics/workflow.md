# Рабочий цикл потребителя

[Раздел](index.md).

Читать сначала этот файл, затем одну карточку/контракт нужного компонента. Весь kit и чужой frontend для обычной задачи читать не требуется.

## Использовать

1. Записать действие пользователя, объект, состояния и фактически доступные API-данные.
2. Найти компонент по назначению/синониму. Карточка содержит статус, version, owner, public import, параметры/defaults/events, ограничения и минимальный пример.
3. Сопоставить задачу с контрактом: отсутствие нужной возможности не угадывать по внешнему виду demo.
4. Связать public inputs/events с controller; применить [проверки по риску](../delivery/testing.md).
5. Обновить usage example при новом подтверждённом сценарии; сообщить ограничения результата.

## Если не хватает

Gap request: task/request IDs, user outcome, найденные кандидаты, точное unsupported состояние, свой вариант API, affected scope. Владелец отвечает контрактом/ограничением/альтернативой; молчание не считается согласием.

После согласования owner меняет свою часть и возвращает версию/путь/evidence. Consumer проверяет стык на реальных данных и действии: готовность двух частей отдельно совместимость не доказывает.

До блокирующей зависимости продолжать независимую работу. Если её нет — сохранить next step и завершить ход. `wait`, sleep/polling и скрытая копия компонента не заменяют ответ владельца.

## Координация

- Реальные UUID/владельцы берутся из актуального [реестра](../../../.codex/agent-team.json), не из вечных docs.
- Поручения, содержательные вопросы, проблемы и нужные итоги — через `codex queue`; проверить exit code и существенный вывод.
- При ошибке доставки сохранить материал/причину и использовать установленный coordinator fallback; не объявлять send_message гарантированным пробуждением.
- Для result вернуть один содержательный итог; для on_problem не будить успехом; не создавать циклы подтверждений.
- Передача файлов/ответственности явная. Изменение общего контракта согласуется с затронутыми владельцами.
- Слова пользователя, текущие требования, своё предложение и принятое решение имеют разный статус; цитировать существенную исходную формулировку без навязанного вывода.

Не найденный новый случай проходит этот же gap-путь; docs дополняются принятой практикой, а не вторым локальным kit.
