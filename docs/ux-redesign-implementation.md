# GhostVault UI redesign — 2026-10-28

Статус: первая реализация `ux-redesign-20261028` отклонена пользователем после просмотра формы соединения и инструкций. Последующая коррекция описана ниже; её пользовательская приёмка ещё не проведена. Источник исходной задачи: `.codex/ux-redesign-task.md`; аудит: [frontend-ux-audit.md](frontend-ux-audit.md).

## Коррекция после пользовательского просмотра

Правила и экспорт, 2026-10-29: по требованию пользователя правила показаны открытыми карточками с примерами, переключателем и удалением; пользовательские выражения видны сразу. Убраны вложенные раскрытия и отдельные кнопки экспорта объектов/разделов. Единственный экспорт в шапке открывает пять групп галочек и скачивает один JSON; при пустом выборе скачивание недоступно. `GET /api/export?groups=connections,patterns,secrets,hooks,proxy,settings` возвращает только выбранные разделы в `data`, `scope=selected`, `included`; неизвестный/пустой список или сочетание с `id` дают 400. Старый API group/id сохранён для совместимости. Выбор настроек включает proxy и settings. Добавлено включённое правило «Любой IP-адрес»: ip-regex распознаёт IPv4/IPv6, node:net isIP подтверждает адрес; короткие `::` и `::1` проходят фильтр. Маркер rule_any_ip_installed устанавливает правило один раз в существующей БД, удалённое пользователем правило повторно не создаётся. Причина: частное IP-правило не покрывало публичные адреса; библиотечный шаблон исключает самописный разбор IPv6. Проверки: TypeScript, UI build, изолированный smoke с фактическим скачиванием выбранных разделов, IPv4/IPv6/границы и сохранение удаления; опубликованные 51 ресурс совпадают с HTTP, live API возвращает новое правило и выбранную группу экспорта.

Тема и JSON, 2026-10-29: пользователь отклонил зелёно-серую палитру. Текущая тема — нейтральные тёмные поверхности, синий акцент, приглушённый светлый текст. Цвета заменены также у вкладок, полей, кнопок, переключателей, подсказок и подстановок. Общий CodeView использует highlight.js core с единственной JSON-грамматикой: ключи/строки/числа/literals/пунктуация различаются цветом, блок имеет метку JSON и рамку. Ui.code и PayloadView.json используют один renderer; интерактивные подсказки подстановок в JSON сохраняются. Строковый исходник не пересериализуется: точность больших чисел и содержимое копирования не меняются. HTML внутри JSON экранируется библиотекой; обычные NAME=value остаются текстом. Проверены классы подсветки, экранирование, точное большое число, plain-text fallback; сборка и isolated smoke прошли. Визуальная приёмка остаётся пользователю.

Инструкции подключения 2026-10-29: Claude Code и OpenCode 2 сначала показывают JSON и точные места файлов, затем отдельное раскрытие переменных формата `NAME=value` без синтаксиса оболочки. Claude: `~/.claude/settings.json`, Windows `%USERPROFILE%\.claude\settings.json`, локально `.claude/settings.local.json`. OpenCode: `~/.config/opencode/opencode.json` либо `./opencode.json` в корне проекта; JSONC допустим. Основание: [Claude settings](https://code.claude.com/docs/en/settings), [Claude env](https://code.claude.com/docs/en/env-vars), [OpenCode config](https://opencode.ai/v2/docs/config), [endpoint](https://opencode.ai/v2/docs/providers#endpoint). OpenCode использует providers.opencode.settings.baseURL без навязывания конкретной модели; ENV-вариант требует ссылки `{env:GHOSTVAULT_BASE_URL}` в этом поле. Это объяснено рядом с NAME=value, чтобы не обещать неподдерживаемую автоматическую переменную. Реальные клиентские конфиги не изменялись. В настройках соединения экспорт и удаление видны без «Дополнительно». Сборка, проверки порядка инструкций/значений копирования и isolated smoke прошли.

Исправление занятых имён 2026-10-29: встроенная предустановка не занимает prefix нового соединения, если она не изменена, не выбрана в workspace и не имеет транзакций. API выдаёт `isUnusedPreset`; создание по такому prefix превращает существующую запись в пользовательское соединение, не создавая лишний маршрут. Реально используемые/изменённые записи защищены от перезаписи. Это устраняет ложный `opencode-2`, вызванный скрытым seed, а не повторными нажатиями пресетов. Удаление соединения также убирает его ID из workspace, чтобы startup seed не возвращал удалённую вкладку. Изолированные проверки создания и защиты занятого имени прошли. Показанный пользователем `opencode-2` исправлен на `opencode` после проверки отсутствия истории; URL сервиса сохранён.

Окончательное уточнение пользователя 2026-10-29: поле «Адрес подключения» целиком удалено из создания и настроек, поскольку оно вводилось для изменения `/v1`, который затем отменён. Форма содержит только название и URL сервиса. Локальный адрес автоматически получается из названия без суффикса и показывается после создания на Обзоре. Удалены preview, обработчик частично защищённого input и связанные стили. Существующие адреса при редактировании названия/сервиса сохраняются; backend compatibility-поле suffix не удаляется из старых данных. Сборка и обновлённый smoke прошли, 51 опубликованный файл совпал с отдаваемым сервером. Эта коррекция заменяет описания адресного поля ниже.

Последняя коррекция 2026-10-29 заменяет описание ниже: адрес представлен ОДНИМ input, основа origin/prefix защищена через beforeinput, полностью выделенный адрес можно копировать. Имя обновляет основу без потери введённого окончания; суффикс по умолчанию пустой. Пользователь отменил автоматический `/v1`: API-путь задаётся upstreamUrl; пресеты OpenAI/Ollama/Zen содержат полный путь, OpenRouter — https://openrouter.ai/api/v1. При публикации 4 существующих окончания `/v1` удалены из локальных адресов с сохранением соответствующего API-пути в upstreamUrl. Собственный `/api/v2` не затрагивается. Причина: два визуальных поля и скрыто добавляемый суффикс не соответствовали требованию единого адреса. Сборка, TypeScript и smoke единого поля/порядка/reload прошли; приёмка остаётся пользователю.

Дополнение 2026-10-29, заменяет прежнюю двухполевую форму: название с примером `opencode` → живая фиксированная основа `origin/prefix` и редактируемое окончание `/v1` → URL сервиса. Случайных названий и скрытия/возврата соединений нет. «+» непосредственно после вкладок; порядок берётся из `workspace.visible`, а не сортировки routes. Preset OpenRouter заполняет name=`openrouter`, upstreamUrl=`https://openrouter.ai/api/v1` ([источник](https://openrouter.ai/docs/quickstart)).

Контракт адреса: create/update route принимают необязательный `suffix`, GET routes возвращает `suffix` и точный `cliUrl`. Пустая строка допустима; `/api/v2` допустим; query/hash/переходы `..` отклоняются. Значение хранится в setting `route_suffix_<id>` и включается в экспорт соединения. Для прежних записей сохранено `/v1`, для встроенного Anthropic — пустое окончание; новый Claude preset заполняет пустое. Клиентские инструкции не переписывают явно сохранённый суффикс. Префикс из названия формируется при создании; переименование существующей записи сохраняет основу адреса. Существующий proxy пересылает путь после prefix, поэтому suffix не подменяет upstreamUrl. Причина: адрес должен совпадать с предпросмотром и копируемой настройкой; скрытое добавление/удаление `/v1` нарушало этот контракт.

Проверки этой коррекции: TypeScript, staging build, isolated smoke с посимвольным изменением названия, пустым suffix, `/api/v2`, порядком вкладок и reload. Визуальная приёмка пользователем не заявлена.

Источник: пользователь потребовал пресеты `name/upstream_url`, заполняющие поля по нажатию; предложил вкладки вместо выпадающего списка, случайное название в placeholder и JSON-настройку в «Другие способы». Отдельное поле локального имени и формулировки неизвестного статуса отклонены. Файл Claude уточнён по официальной документации: [settings.json](https://code.claude.com/docs/en/settings), [env](https://code.claude.com/docs/en/env-vars).

## API и состояние

- `GET /api/workspace`: `{visible: string[], selected: string}`. Без сохранённого выбора: custom/изменённые маршруты и маршруты из последних 1000 транзакций; это восстановление видимости, не миграция самих маршрутов.
- `POST /api/workspace`: тот же объект; ID проверяются; хранение в `settings.dashboard_workspace`. Скрытый маршрут остаётся работоспособным и возвращается через добавление.
- `POST /api/routes/:id`: прежний `upstreamUrl`, дополнительный `name`; prefix не меняется, существующие адреса клиентов сохраняются.
- `GET /api/client-help`: фактический URI установленного дополнения Zen.
- `GET /api/export?group=all|connections|patterns|secrets|hooks|proxy|settings&id=...`: `format=ghostvault-settings`, `version=1`, `exportedAt`, `scope`, `data`, `note`. `id` применим к группе; неизвестная группа 400, отсутствующий объект 404.
- Полный `data`: соединения, правила, ручные/авто секреты с реальными значениями и происхождением, действующие параметры прокси, сохранённые настройки, известные хуки. Загруженные из файлов хуки содержат исходный модуль; программно переданные хуки отмечены как требующие исходного приложения. Зависимости модулей не упаковываются.
- Все новые `/api/*` используют существующий origin/host guard. Протокол маскирования и настройки внешних клиентов не менялись.

Почему: видимость рабочего соединения и реальные маршруты выполняют разные задачи. Для чего: сократить интерфейс без потери данных и дать переносимый снимок настроек. Как: отдельные настройки рабочего пространства и версия экспортного формата. Почему не иначе: массовое удаление предустановок или экспорт только отображаемых масок повредили бы рабочую конфигурацию.

## Проверки

- `npm run build:ui:stage`, `npx tsc` — frontend и backend собираются.
- `ui-kit`: `npm run check`, `npm test` — типы, стиль, 38 unit/contract tests.
- `ghostvault`: `UI_BUILD_DIR=<staging> npm run smoke:ui` — отдельная SQLite `:memory:`, Chromium, внешние запросы блокируются; реальные пользовательские данные не участвуют.
- Smoke: пустой workspace, шаблон и custom-соединение, переименование, примеры клиента, hash/reload, черновик секрета, точный alias с lowercase/Unicode/спецсимволами, закрепление/ARIA, отдельное копирование, экспорт, отсутствие реконструкции старой записи, таблица 390 px, неизвестное событие.
- `npm run check:ui`, `npm run test:admin`, `node dist/test-gateway-regressions.js` — локальные ресурсы, guard новых API, существующие операции и маршруты.

Ограничения: пользователь проверяет дизайн; physical touch, screen reader, другие браузеры и реальные клиентские подписки/модели не проверялись. Экспорт не восстанавливает произвольные программные closures хуков и настройки сторонних приложений. Политика хранения истории/бюджет 200 МБ не входит в изменение UI.
